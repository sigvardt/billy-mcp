# ui_daybooks_delete_open shell

Tool `ui_daybooks_delete_open` opens path class `/:org_slug/daybooks/:id`, opens **Mere** observe-only, and classifies **Slet** text in the menu body (export CSV/XLS + Importér + Slet). Primary Slet button is absent. Never confirms delete.

Disposable empty daybooks expose Slet; some system journals show export/import only. The product prefers daybooks that expose Slet after Mere.

Related NA freezes from the same dual observation: `daybooks.update` (no update form), `billLines` get/list/create/update/delete (embedded on bill edit only), `users.get` + `users.update` (Brugere list panel only). Bulk rows stay external-contract red. API `live_tested` remains false with `out_of_scope_by_user`.
