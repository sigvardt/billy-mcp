# 171.1 Typed auth status workflow

Implement one read-only, fail-closed `auth_status` tool in the permitted
browser, model, and server files. No delegation is possible: this node is a
leaf (`max_depth`, `max_children`, and `max_descendants` are all zero).

1. Add strict Pydantic contracts for the empty input and the only verified
   status (`AUTH_REQUIRED`), using the existing structured `ToolError` for
   fail-closed outcomes.
2. Extend `BrowserRuntime` only with an internal auth-status operation: start
   the existing headless persistent context, open the fixed Billy root URL,
   require the exact final `/login` URL and the observed email, password,
   remember-me, and Danish/English submit signature, then return either the
   verified status or a redacted `UI_CHANGED`/runtime error. Do not expose a
   navigable, selectable, clickable, typable, or inspectable browser surface.
3. Register `auth_status` from `create_server` with an injectable
   auth-status-only runtime seam. Its public handler has no generic parameters,
   validates the empty Pydantic input, and returns only the typed union.
4. Add focused tests for the known login state, route/signature drift,
   headless and allowlist behavior, secret-free runtime failures, empty tool
   schema, registration, and server invocation. Update the existing aggregate
   registration assertion without changing any coverage artifact.
5. Run formatter, Ruff, Pyright, focused tests, and the required non-live node
   test command. Inspect the final diff to confirm that `coverage/` and every
   UI row remain untouched, then commit, report the exact evidence and the
   mandatory post-merge Grok review, and finish the node.

## Post-Mortem

Implemented the fixed-root, headless-only `auth_status` check with strict
English/Danish login signatures, typed redacted outcomes, and a narrow injected
runtime seam. Focused tests cover recognised login, route and signature drift,
DOM-read failure, headless launch, allowlist enforcement, registration, and
redaction. No coverage artifact changed; no live login, credentials, browser
session contents, or UI qualification claim was made. The parent merge still
requires the mandated independent Grok review.
