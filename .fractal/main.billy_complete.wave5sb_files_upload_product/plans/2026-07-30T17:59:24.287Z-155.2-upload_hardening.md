# 155.2 Wave-5s-B upload boundary hardening

## Scope and decision

This node is a leaf: all child limits are zero, so the two coupled boundary
repairs remain one local implementation task. The committed slice already
contains the required binary upload service, narrow client path, registration,
coverage evidence, and non-live tests. Only the verified strict-input and
header-injection defects remain; `ConfirmationStore`, the JSON write protocol,
inventory structure, UI, live, bulk, and external research are out of scope.

## Execute

1. In `src/billy_mcp/api/file_upload_writes.py`, use strict Pydantic scalar
   annotations on the registered FastMCP function parameters so the framework
   itself cannot coerce string booleans or numeric strings before the strict
   input models run. Preserve exactly the two existing tool names and flat
   schemas. Reject CR/LF in all tool-derived header values during preview.
2. In `src/billy_mcp/client.py`, add one narrow local validator for the three
   caller-derived header values (`X-Filename`, `Content-Type`, and optional
   `x-organizationid`). Keep the existing fixed `/files` path, fixed base,
   client-owned token/accept headers, optional-header allowlist, raw bytes,
   error mapping, and zero retry policy unchanged.
3. Extend only the directly relevant tests. Exercise the real FastMCP tool
   boundary with rejected coercions and CR/LF values before any HTTP, and prove
   `post_file` rejects each CR/LF injection attempt before mock transport sees a
   request. Retain the existing contract coverage for identity, tickets,
   headers/body, redaction, aliases, and coverage rows.
4. Format and run the focused upload/client/registry/coverage tests. Regenerate
   coverage, verify the generated totals and false-completeness guard, then use
   the full non-live, static, policy, and dependency checks during verification.

## Acceptance checks

- Actual FastMCP calls reject non-boolean optional flags, non-string text, extra
  inputs, and CR/LF header values without issuing HTTP or a ticket.
- The public narrow client cannot construct arbitrary headers through the three
  tool-derived string values and sends no request on rejection.
- Both inventory rows remain implemented and contract-tested; the alias keeps
  an empty `tool_name`, API tools remain 267, and `complete` remains false with
  no live/vision/bulk claim.
