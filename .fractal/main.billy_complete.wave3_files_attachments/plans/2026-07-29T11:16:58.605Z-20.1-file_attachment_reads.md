# 20.1 File and attachment read tools

## Scope and decision

This is a leaf node (all child limits are zero), so the two owned files will be
implemented and verified directly. The cited Grok brief and the frozen Wave-3
contract are sufficient evidence; no further external research or live calls
are needed.

## Delivery

1. Create `src/billy_mcp/api/file_attachment_reads.py` following the strict,
   typed reference-data/read-service pattern: opaque allow-extra record and
   paging models; separate get/list input and success models; URL-encoded item
   paths; and a module-local registration function exposing exactly the four
   files/attachments tools.
2. Restrict collection inputs to `page`, `pageSize` (1–1000), `include`, free
   `sortProperty`, and `ASC`/`DESC` `sortDirection`. Get inputs accept only a
   non-empty `id` and optional `include`. Return the client’s existing typed
   errors unchanged, including 401 authentication mapping.
3. Add a mock-transport contract suite for encoded item and collection paths,
   exact query surface, singular/plural roots plus optional paging, forbidden
   fields and invalid bounds/directions, the two documented 401 envelopes, and
   exact registration. Fixtures will contain no token-bearing `downloadUrl`.
4. Run focused pytest, Ruff format/check, and Pyright; repair only the two
   owned files. Commit the scoped result, then report the commit and the
   deliberately excluded root registration, coverage, and live claims upstream.

- Delivered the four typed files/attachments get and list handlers with strict
  inputs, URL-encoded identifiers, opaque records, optional paging, and
  module-local registration.
- Added 15 mock-transport tests covering paths, query construction, roots and
  paging, rejected inputs, both authentication envelopes, and registration.
- Independent review passed the frozen contract. Its `downloadUrl` redaction
  observation belongs to the root-owned redaction layer; root confirmed its
  shared fix in `9555d79`, and this leaf neither logs nor fetches download URLs.
- Evidence: focused tests pass; commit-mode test script passes 143 tests; Ruff

  correctly fail closed because global coverage remains incomplete (92
  ambiguous bulk rows, 305 API rows, and 339 UI rows).
- No live calls, UI work, writes, uploads, root registration, or coverage
