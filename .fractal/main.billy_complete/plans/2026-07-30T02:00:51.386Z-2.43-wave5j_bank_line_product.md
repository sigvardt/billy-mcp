## Implementation and verification contract

1. Clone the Wave-5i write-module pattern without expanding `bank_reads.py`.
   Register exactly eighteen tools through the root's shared
   `WriteProtocolService`: create/update/delete preview+execute pairs for all
   three frozen resources.
2. Build specs with the exact collection/singular/plural roots. Match writes
   alone may map optional `bankLines` and `bankLineSubjectAssociations`; line
   and association writes must not invent a parent root. Deletes are bodyless;
   update-body `id`, when supplied, must equal the route id.
3. Add real local contract tests for schemas, mutation-free previews, canonical
   binding, escaped paths, singular bodies, bodyless deletes, required/optional
   response roots, deleted metadata, auth error mapping, ticket tampering,
   expiry, replay, and one-request/no-retry behaviour. Add a root-server
   cross-executor test proving a ticket remains unconsumed after same-resource
   and cross-resource executor mismatch.
4. Update the root registry assertion from 220 to 238. After the tests are
   real and passing, mark only the nine singular manifest rows `implemented`
   and `contract_tested`; leave their `live_tested` false, leave all six related
   bulk rows tool-less/red, regenerate coverage status to 166 offline rows and
   `complete: false`.
5. The child runs focused format/lint/type/unit/contract/safety checks and
   records exactly what passed. The parent will inspect the committed diff,
   merge with `--no-ff`, run repository checks, and then spawn an independent
   Grok product review against the merged bytes.
