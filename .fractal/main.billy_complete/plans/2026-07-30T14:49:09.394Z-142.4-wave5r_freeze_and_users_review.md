# 142.4 Wave-5r freeze authoring and Wave-5q product review

## Decision

The cited Research73 package already in the root worktree authorises a
**wiki-only** contract freeze for `api.salesTaxReturns.update`; it does not
authorise product code or coverage greening. The merged users-update product
also requires an independent review. These are independent, bounded tasks with
disjoint owned files, so two child leaves are warranted:

1. Codex Power authors the Wave-5r freeze contract.
2. Grok independently reviews the already-merged Wave-5q users product.

Do not parallelise the later Wave-5r product or freeze review: both depend on
the freeze page and its independent acceptance. Do not conduct a Codex review
as a substitute for the required Grok review.

## Baseline and safety gate

1. Preserve the existing Research73 artifacts, root state update, and this
   plan; inspect the diff and run `wiki lint` on the project wiki.
2. Run the commit-mode format, lint, type, unit, contract, coverage-policy, and
   repository-policy suite, then make one root baseline commit before child
   initialization. The children must fork the cited research and the merged
   users source, not uncommitted files.
3. Keep `api.salesTaxReturns.update`, every live/vision flag, all UI rows, and
   all ambiguous bulk rows red throughout this iteration. Never test or write
   live Billy data without the dedicated non-production credentials.

## Child A — Codex Power freeze authoring

Create `wave5r_sales_tax_returns_freeze` as a childless `--agent=codex-power`
leaf after the baseline commit. Its exclusive product ownership is:

- `wiki/wave_fiver_ticketed_writes_contract.md`
- `wiki/_index.md` (the derived index entry for that page only)

The execute-step spawn sequence is explicit and must run only after the root
baseline commit succeeds:

```sh

  --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
  --base=main.billy_complete --agent=codex-power \
  --max-depth=0 --max-children=0 --max-descendants=0 \
  --title='Wave-5r Sales-Tax-Returns Freeze Contract'
fractal node init wave5q_users_product_review \
  --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
  --base=main.billy_complete --agent=grok \
  --max-depth=0 --max-children=0 --max-descendants=0 \
  --title='Wave-5q Users Product Independent Review'
```

Configure each leaf's `NODE.md` with the file ownership and completion limits
below, commit its configuration from its own worktree with `fractal commit
"configure <leaf>" --init`, then start both branch names from the root. The
leaves have no cost or iteration cap because the node is explicitly uncapped.

Its page must cite `wave_fiver_sales_tax_returns_freeze_ready_research` and
freeze exactly these future tools, with no source changes:

| Inventory id | Preview | Execute | Request | Required root |
| --- | --- | --- | --- | --- |
| `api.salesTaxReturns.update` | `api_sales_tax_returns_update_preview` | `api_sales_tax_returns_update_execute` | `PUT /salesTaxReturns/:id`, outer `{id, salesTaxReturn}` | `salesTaxReturns` |

Require strict outer input, opaque inner map, optional inner-id/path-id match,
ticket-only single-use execution of at most five minutes, exactly one no-retry
write, and response mapping limited to `salesTaxReturns`. The contract must
record official Supports/property boundaries and the observed POST 405, PUT
401, DELETE 405, and empty-body PUT 400 gates. It must explicitly exclude
create, singular delete, bulk, webhooks, generic HTTP/browser controls,
field-level writable claims, product source/tests/registration, coverage
greening, live/UI/vision work, and cleanup/reversibility claims.

The leaf validates its wiki output and commits it. Its completion is authoring
only—not freeze acceptance or product authority.

## Child B — Grok users product independent review

Create `wave5q_users_product_review` as a childless `--agent=grok` leaf after
the same baseline commit. Its exclusive product ownership is only
`wiki/wave_fiveq_users_product_independent_review.md`; it must not edit
`wiki/_index.md`, source, tests, manifests, coverage output, or node state.
The parent will regenerate the index after merging both leaves.

The review targets the exact merged root source from the baseline commit:
`src/billy_mcp/api/user_writes.py`, its server registration, user-write tests,
coverage generator mapping, manifest/status output, and registry-count test.
It must independently re-fetch and cite the current official Billy docs,
review the 401/405 method-gate evidence, verify the two-tool surface, strict
outer/opaque-inner boundary, route/body and root mapping, ticket binding and
no-retry semantics, redaction, and offline-only coverage arithmetic. It must
give an unambiguous ACCEPT or REJECT and retain no sensitive/raw evidence. It
must not claim live, UI, vision, cleanup, or completeness acceptance.

## Integration after child completion

1. Monitor both leaves, read their outboxes, and merge only their committed
   outputs with labelled no-fast-forward merge commits.
2. Run `wiki update` and `wiki lint` on root to reconcile the root index,
   re-check links, and retain only generated index changes.
3. If the Grok verdict is ACCEPT, record the Wave-5q offline product acceptance
   in durable state. If REJECT, keep its row honest and route the specific
   finding to Codex Power repair work.
4. The Wave-5r product remains blocked until an independent Grok freeze review
   accepts the merged freeze page. Only then may a separate Codex Power product
   leaf implement its two tools and advance offline coverage from 178 to 179.
