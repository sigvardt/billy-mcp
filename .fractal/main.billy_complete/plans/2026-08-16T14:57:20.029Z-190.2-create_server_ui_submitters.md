# 190.2 Arm create_server UI submitters and require org binding

## Goal

Make the default FastMCP server path able to submit UI writes. Today
`create_server` registers seven families with only `(server, ui_write_protocol)`.
Products and ledger execute consume the ticket and return. Bills, invoices,
files, and organizations default to unarmed or unconfigured submitters.
Contacts alone builds a `BrowserRuntime` actor. Previews pass
`organization_id=None`.

## Baseline

HEAD after the seven family merges. Coverage `complete=false`. Sixteen CUD

## Design choices

1. **TDD first.** First product edit is a failing unit test on `create_server`.
   Run it. Capture the failure. Then implement.
2. **One shared browser.** Pass the `BrowserRuntime` that `create_server`
   already builds into every `register_ui_*_write_tools` call. Do not spawn a
   second default runtime per family. Tests may still inject a fake actor.
3. **Organisation id is required.** `UiWriteProtocol.preview` rejects a missing
   or blank `organization_id` with `ORGANIZATION_REQUIRED`. Every preview tool
   takes a required `organization_id: str` (min_length=1). Callers prove the
   dedicated non-production org in the interface first (later live slice). This
   slice only makes the ticket refuse to issue without that id.
4. **Execute must reach a browser actor.** After a valid ticket, execute calls
   a `BrowserRuntime`-backed submitter. Consume-only success is illegal on the
   default path.
5. **Fail-closed stays fail-closed.** Invoice actor may create/update/delete
   drafts only (never Godkend/send/email). Org actor may touch the already
   scoped company field only (never users/tokens/subscription). Files still
   bind path+digest. Ledger actor may exist; it must not invent a delete-less
   irreversible posting submit if the family still lacks a proven cleanup
   path — refuse with a typed `ToolError` rather than a silent consume.
6. **No greening.** Honesty set stays 16. `tool_name` stays on `*_open` tools.
