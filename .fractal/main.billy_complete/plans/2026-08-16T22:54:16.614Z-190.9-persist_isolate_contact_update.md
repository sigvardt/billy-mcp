## Design choices

1. **TDD first.** First product edit is a failing persist-isolate unit test.
   Run it. Capture the failure. Then implement.
2. **Keyboard only if the value is wrong.** If `input[name=name]` already
   equals `{tag}-U`, do not fill again. If it differs, Meta/Control+A, type,
   Tab or blur, then recapture. Then click save at most once.
3. **Update clicks only `button[data-cy='save-button']`.** Remove xpath **Gem**
   from the update path. Create dialog save stays last exact **Gem**.
4. **Stay on the customer page after the click.** Capture before and after:
   name value, save-button disabled / aria-disabled, visible
   `[role=alert]` / error / toast text. Watch the browser XHR to
   `/v2/contacts` (method, status, redacted JSON keys). No token. No raw body.
5. **List proof only after a 2xx interface response.** No request, old name
   in the request, or a visible error: return `UI_CHANGED` with those
   `details`. Do not search `/clients` and call that `NOT_FOUND`.
6. **One tag.** `MCP-UI-C-<8hex>`, then `{tag}-U`. No second create.
7. **Live qualification uses `create_server()` `call_tool`.** Vision stays
   `pending_review`. No greening.
8. **Keyring refs on.** `BILLY_ORGANIZATION_ID` unset until READY returns the
   live slug.
