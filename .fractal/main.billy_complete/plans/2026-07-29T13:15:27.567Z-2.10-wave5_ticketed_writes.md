# 2.10 Wave 5 ticketed clear writes

## Objective

Start the next bounded, evidence-backed implementation slice without claiming
product completeness: ticketed create, update, and singular delete tools for
products, product prices, contacts, contact persons, and daybooks. This is
fifteen inventory operations and thirty registered `api_*` tools. The target is
offline implementation and contract evidence only; live, UI, vision, bulk,
special-route, and completeness states remain red.

## Contract and current evidence

The current Grok brief at `.fractal/main.billy_complete/tmp/grok-research.md`
is contract-bearing: official documentation fingerprint `hsisik4g9p3603` /
`c2efda0ee4cf9cf200e14910c5fc6996`, rechecked on 2026-07-29. It establishes
singular-root POST/PUT bodies, bodyless singular DELETE, changed-record roots,
and `meta.deletedRecords` without inferring any bulk body. It also records that
unauthenticated DELETE's empty 200 response is never cleanup proof. The
approved design requires preview plus an exact, five-minute-or-less, single-use
execute ticket; execute accepts only the ticket.

Before any child starts, promote this cited boundary into the tracked project
wiki as `wiki/wave_five_ticketed_writes_contract.md`. Include the fifteen
inventory IDs, routes, roots, preview/execute pair naming, binding fields,
strict non-claims, and citations to the official docs, the design, the inventory,
and the Grok brief. Refresh and lint the wiki. This turns scratch research into
a merge-safe contract without copying credentials or raw probe material.

## Delegation decision

The write protocol and four resource clusters are separable, each needs a
clean implementation/test context, and their product-file ownership can remain
disjoint. Root will manage integration rather than implement resource tools.
Existing cited Grok research satisfies the required research-before-implementation
gate; a new independent Grok review occurs after the root integration.

   policy checks before spawning. Children must branch from this committed
   contract, never from uncommitted root files.
