## Design choices

1. **TDD first (`728BD2E4`).** First product edit is a failing unit
   fixture. Current live five `other_v2` rows fail
   `kunde_route_missing_keys`. Run it. Capture the failure. Then
   implement. Do not reuse `REQUIRED_KUNDE_TRACE_KEYS` or
   `REQUIRED_KUNDE_EVENT_KEYS` as this fixture.
2. **Honesty-16 stays red.** Confirm the coverage gate still
   length 16 before any other edit.
3. **Keys are allowlisted tokens and buckets.** Never store raw
   URLs, query, body, header, token, UUID, numeric id, org slug,
   or customer text in git.
4. **Listeners first.** Request listeners attach **before**
   `goto /invoices/new`. Classification uses the SPA request the
   page already issued. Do not `fetch` or `goto` a `/v2/` URL.
5. **`route_class`.** First `/v2/` segment when it matches the
   fifty official tokens in the research brief. `contacts` and
   `invoices` stay those tokens. Unknown `/v2/` stays `other_v2`.
   Hosts outside the Billy allowlist stay `denied`.
6. **`timing_bucket`.** `0_49` / `50_99` / `100_249` / `250_499`
   / `500_plus`. Do not require raw `timing_ms` on the new keys.
7. **`phase`.** First observation only: `at_rest`, `after_click`,
   or `after_type`. The five known rows are expected at `at_rest`.
8. **Sanitized template (owner-only).** Strip query. UUID →
   `:uuid`. Long hex → `:id`. Digit segment → `:n`. Write to
   `~/.local/share/billy-mcp/` only. Purge after review if anything
   beyond the template remains.
9. **Contact-adjacent.** `contact_dataset_preloaded=true` only
   when a first-seen `route_class` is `contactPersons`,
   `contactBalancePayments`, or `contactBalancePostings` (or
   another official token that starts with `contact` and is not
   `contacts`) and `phase=at_rest`.
10. **Named next action.** True only when
    `contact_dataset_preloaded` is true. The only allowed product
    fix is wait/state on that `route_class` before type. Five
    still-unnamed `other_v2` rows after capture means
    `UI_CHANGED`.
11. **Instrumented click + type are allowed once.** Center click
    the proved `input[name=contact]`. Then type the exact FastMCP
    tag with the existing sequential path. Listeners are already
    on. This is not a `4A5CD1E7` repeat.
12. **Cleanup.** Delete the tagged customer through FastMCP in a
    fresh session. Prove absence. Do not leave `MCP-UI-INV-*`
    contacts.
13. **Do not remap.** Preview `tool_name` waits for a later slice
    after independent accept + purge.
14. **Vision.** Live test may write `author=live_test` and
    `reviewer_verdict=pending_review` only. Field shot and
    owner-only template file live under `~/.local/share/billy-mcp/`
    and are purged after review.
