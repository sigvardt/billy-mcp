# 110.15 Wave-5q independent review gates

## Decision

Run two isolated Grok review leaves in parallel. The required freeze review and
the independent review of the already-cited product-ready research have no
shared writable deliverables: each owns one new wiki page. Product code remains
blocked until the freeze review is merged with an ACCEPT verdict.

This is a management iteration. The root branch already contains the Wave-5q
freeze contract; the discovered research-ready package and this plan are
committed before either reviewer starts so both review the same baseline. There
were no running children when the split was chosen.

## Evidence and boundaries

- Official-document brief: `.fractal/main.billy_complete/tmp/grok-research.md`
  (research71), mirrored by
  `wiki/wave_fiveq_users_product_ready_research.md`.
- Contract under review:
  `wiki/wave_fiveq_ticketed_writes_contract.md`, freezing only
  `api.users.update` as `api_users_update_preview` and
  `api_users_update_execute`.
- Method gates: users PUT with JSON `{}` is 401; POST and singular DELETE are
  405. The only possible offline product is the singular update pair.
- Coverage stays at 177 offline rows; all live, UI, vision, and bulk claims
  remain red. Neither review may modify source, tests, manifests, status, or
  coverage reports.

## Child leaves

1. `wave5q_freeze_review` (`--agent=grok`)
   - Owns `wiki/wave_fiveq_freeze_independent_review.md` only, plus its own
     node directory.
   - Independently validate the frozen contract against the cited official
     docs/research71, current root inventory, ticket protocol, sensitive
     fields, exact two-tool scope, 401/405 gate evidence, and exclusions.
   - Deliver an explicit ACCEPT or REJECT. ACCEPT may authorise a future
     Codex Power users-update product leaf, but cannot authorise live/UI/bulk
     work or green coverage.

2. `wave5q_product_ready_review` (`--agent=grok`)
   - Owns `wiki/wave_fiveq_users_product_ready_research_independent_review.md`
     only, plus its own node directory.
   - Independently validate research71 and its durable wiki mirror against the
     current docs/inventory and confirm the exact post-freeze Codex Power
     implementation surface. Deliver ACCEPT-as-research or REJECT only.
   - It cannot accept the freeze contract, implement tools, or alter coverage.

## Integration and next decision

1. Monitor both leaves and merge their wiki-only outputs with `--no-ff` when
   complete; repair generated wiki-index rows and run the documented checks.
2. If the freeze review is ACCEPT, open a new Codex Power leaf for only
   `src/billy_mcp/api/user_writes.py`, its API tests, server registration, and
   the one honest `api.users.update` coverage row. Do not start it earlier: the
   freeze verdict is an external gate it cannot satisfy itself.
3. If either review rejects, preserve the cited finding, repair only the
   identified boundary, and request a focused Grok re-review before code.
4. Keep Wave-5r sales-tax-return work, ambiguous bulk rows, UI/auth/vision,
   live qualification, and all other write areas out of this iteration.
