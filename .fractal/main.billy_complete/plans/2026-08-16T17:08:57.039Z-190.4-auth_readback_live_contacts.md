## Design choices

1. **TDD first.** First product edit is a failing FastMCP unit test. Run it.
   Capture the failure. Then implement.
2. **READY returns `organization_id`.** Field name is `organization_id`, never
   `org_slug` (schema forbids secret-looking `org_slug`). Value is the live
   URL first path segment. `AUTH_REQUIRED` leaves it null. Do not read the
   identity file for this value. Do not invent a new error code.
3. **One login sequence owns both sessions.** Keep
   `auth_login_start` / `auth_login_wait`. After the write profile is READY,
   run the same configured-ref login on `independent_readback_runtime()`.
   Same slug required. Mismatch is `CONFIRMATION_MISMATCH`. Read-back still
   on `/login` after start is `ORGANIZATION_REQUIRED`.
4. **Catch-up when write is already READY.** If the write profile is already
   a dashboard and the `-readback` profile is `/login`, `auth_login_wait`
   must still log in the read-back profile. Do not fail the write start just
   because the write session is already restored.
5. **Live test uses `create_server()`.** Prefix
   `BILLY_BROWSER_PRIMARY_REFERENCE=billy-ui-primary` and
   `BILLY_BROWSER_SECONDARY_REFERENCE=billy-ui-secondary`. Set
   `BILLY_BROWSER_PROFILE` to an owner-only temp dir so the default MCP
   profile is not required. `BILLY_ORGANIZATION_ID` stays unset. Qualify
   only through `call_tool`.
6. **Green only after live pass.** Honesty set stays 16 until the live test
   and vision record exist. Then lift only the three contacts ids.
