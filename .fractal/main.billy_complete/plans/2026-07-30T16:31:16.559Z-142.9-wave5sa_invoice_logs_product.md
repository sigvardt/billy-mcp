## Decomposition decision

The product is a bounded but multi-file implementation with independent test
and coverage consequences, so a dedicated **Codex Power leaf** owns it. The
mandatory Grok product review cannot run in parallel because it must inspect
the merged implementation. No other residual area is spawned: its contract is
not part of this product slice.

   cited contract.
2. Create and configure a `codex-power` leaf named
   `wave5sa_invoice_logs_product`, with ownership limited in its `NODE.md` to:
   `src/billy_mcp/api/invoice_log_reads.py`,

   `tests/unit/test_coverage_server.py`,
   `scripts/generate_coverage_report.py`, and generated `coverage/` artifacts.
   It must not modify wiki research or work on any other special/API/UI row.
3. Give the leaf this acceptance contract:
   - expose one strict typed FastMCP tool, `api_invoice_logs_list`;
   - require nonempty `invoiceId` and `organizationId`; emit only
     `sortProperty=eventTime` and `sortDirection=DESC`; accept no paging,
     undocumented filters, singular get, or write surface;
   - map the exact `invoiceLogs` list root to typed opaque entries, preserve
     typed auth errors, fail closed on a malformed root, and register the tool
     on the real server;

   - add only `api.special.invoice_logs` to generated offline implementation
     evidence, regenerate artifacts, and verify 265 API tools and
     180/180/0/0 coverage with `complete: false`.
4. The leaf runs formatter, Ruff, Pyright, its API and registry tests,
   coverage generation and integrity check, then the non-live/non-vision suite.
   It must report the exact commands and results, make no network, browser,
   credential, or live-data calls, and leave no raw evidence.
5. While the leaf runs, manage its trajectory only. When it commits, review its
   three-dot diff and merge it with a labelled no-fast-forward merge if the
   product contract is satisfied. Then start a separate `grok` review leaf to
   independently recheck current docs, the list-only surface, query freeze,
   method gates, tests, and coverage honesty. An ACCEPT is offline only.
