## Design decisions

### 1. Check `remember` in product `auth_login_start`

Sequence (fail-closed, re-check login signature between steps as today):

1. Validate known login page.
2. Resolve primary + secondary credential references (no logging values).
3. Re-check signature; fill email.
4. Re-check; fill password.
5. Re-check; if `input[type='checkbox'][name='remember']` count==1 and visible,
   set it checked (Playwright `check()` or equivalent). Missing control →
   `UI_CHANGED` (remember is part of the recorded login signature already via
   `_LOGIN_CONTROL_SELECTORS` count==1).
6. Re-check; click submit; settle; return `AUTHENTICATING`.

Protocol: extend `LoginControl` with `async def check(self) -> None` so fakes
can record `check:input[type='checkbox'][name='remember']` without using fill.

Do not accept remember as a tool input. Always set true when the control is
present (persistent profile design).

### 2. Independent second interface for live e2e

Mandatory path:

| Session | Profile | Sequence | Assert |
| --- | --- | --- | --- |
| A | ephemeral under `~/.local/share/billy-mcp/` (not repo) | status → start → wait | wait `READY` |
| B | **different** ephemeral profile | status → start → wait | wait `READY` |

No page/DOM objects shared between A and B. No API client. No token.

Optional third (product regression for remember):

| Session | Profile | Sequence | Assert |
| --- | --- | --- | --- |
| A restore | same profile as A after `close()` | new runtime, `auth_login_wait` only | `READY` |

Skip live tests when credential env refs missing (`pytest.mark.live` + skip).
Never skip as green for completeness.

### 3. DOM assertions (non-PII)

- Wait status is `READY` (typed success).
- Optional open page on same runtime only if needed for extra DOM: path matches
  `_DASHBOARD_PATH` class (assert via private helper or re-export test-only path
  class function that never returns the slug). Prefer trusting
  `AuthLoginWaitSuccess(status="READY")` already encoding path+marker checks.
- Org identity: assert outside-git file exists and `slug_present` / length
  equality between A and B without reading slug into pytest assert messages
  (compare lengths or hash of slug in memory, never print).
- Post-login `auth_status` may return `UI_CHANGED` when already READY — do not
  treat that as failure (research101 §3.4).

### 4. Vision evidence (auth READY only)

- Capture one headless frame per session (A and B) to owner-only temp
  (`tempfile` under `/var/folders` or `~/.local/share/billy-mcp/vision-tmp/`).
- Durable record written under
  `.fractal/main.billy_complete/tmp/vision-records/` (gitignored via `tmp/`)
  **or** a non-secret path under coverage only if the schema allows
  `vision_evidence` without embedding frames. Prefer tmp + wiki pointer.
- Record fields only: workflow ref (`auth.login.ready` or tool names), run id,
  assertion refs, second-interface ref, reviewer placeholder for REVIEW step,
  timestamp, `purge_verified` after delete.
- EXECUTE may leave `verdict: pending_review` and purged frames; REVIEW/IR
  supply verdict. Do not commit PNG/HAR/trace.

### 5. Coverage honesty

- Do **not** set any API `live_tested` true.

- Status blocker may mention auth live path progress but must not claim
