## Design choices

1. **TDD first (`728BD2E4`).** First product edit is a failing unit
   fixture: `page_flow._fill_named` on `contact` is not a Kunde bind
   when the visible control is `contactId` / combobox / portal.
   Run it. Capture the failure. Then implement.
2. **Existing-option Kunde bind.** Reuse the bills idea
   (`pick_portal_existing_option_index`), not the bills vendor
   module as a shared generic helper. Invoice-local code. Create
   footer is last resort only when no exact option exists.
3. **Tagged contact first.** `ui_clients_create_preview` /
   execute, then invoice CUD, then invoice delete, then contact
   delete. Reverse dependency order. Third-session absence for both.
4. **Observe before CTA changes.** Keep fail-closed
   **Gem som kladde** until a live dump shows **Opdater**. Then a
   failing fail-closed test, then the allowlist change.
5. **PUT egress only after a failing test.** If update XHR is PUT
   and is denied, add the failing egress test first, then prefix
   PUT `/v2/invoices/` only. PATCH and emails stay denied.
6. **Vision provenance (`C7DBE974`).** Live test may write
   `author=live_test` and `reviewer_verdict=pending_review` only.
   Do not accept or purge frames.
7. **Do not remap.** Preview `tool_name` wait until a later slice
   after independent accept + purge.
