## Delegation decision

The two product leaves have disjoint source and test-file ownership, so they
will run in parallel. The root retains all shared files and integration to avoid
server/coverage conflicts. A Grok reviewer must run only after the merged root
is independently testable; it is therefore not launched with the implementation
leaves.

## Feasibility

There is no time or cost cap. The root plus two concurrent implementation
leaves uses three of the four available slots, leaving the final reviewer
deferred until the leaves finish. No child starts until the research baseline is
committed, so both receive the durable contract from their branch base.

1. Promote the cited Wave-5b contract to
   `wiki/wave_fiveb_ticketed_writes_contract.md`, refresh the project wiki, and
   commit the research baseline before creating children. This makes the
   contract available from each child branch rather than relying on scratch.
2. Initialise and configure two child nodes with explicit routing:

   ```sh
   fractal node init wave5b_account_writes --path=/Volumes/ssd_1/Repositories/billy-mcp --agent=codex-power --max-iters=8 --max-depth=0 --max-children=0 --max-descendants=0
   ```

     `src/billy_mcp/api/account_writes.py` and

- Each operation maps POST/PUT/DELETE to the documented collection with a
  singular request root; delete has no body.
- Preview and execute tests prove exact ticket binding, replay and tamper
  rejection, non-mutation on preview, and request method/path/body on execute.
- Neither accountNatures nor postings writes are added: their current
  unauthenticated 405 observations are a later authenticated-evidence blocker.
- No coverage row receives `live_tested=true`, no UI row changes, and
  `complete` remains false.
