# 2.1 Phase 0 inventory and shared foundation

## Objective

Land the first production-quality, non-stubbed Phase 0 slice from the approved
design: a red, source-traceable inventory; safe shared infrastructure; a
typed FastMCP stdio shell exposing only real `coverage_*` operations; and the
test/CI baseline. Do not claim completeness or turn any row green.

The contract input is `.fractal/main.billy_complete/tmp/grok-research.md`,
whose primary evidence is https://www.billy.dk/api/ with fingerprint etag
`hsisik4g9p3603` / MD5 `c2efda0ee4cf9cf200e14910c5fc6996`. Treat its 92 bulk
operations and singular `/v2/organization` sample as ambiguous. Keep every
`live_tested` field false while `BILLY_API_TOKEN` is unavailable.

## Existing state and constraints

- Preserve the present uncommitted memory update: it records the refreshed
  research and restored write access.
- The repository has no implementation, package metadata, coverage directory,
  tests, or CI. The current test script has a pre-foundation soft pass; extend
  it so a full qualification run cannot succeed without a project.
- Use Python 3.12, uv, Pydantic, FastMCP, Ruff, Pyright, pytest, and Playwright
  Chromium. Browser code must always set headless mode and use the configured
  profile outside git.
- No credential, cookie, browser frame, HAR, trace, upload, generic HTTP,
  generic browser, dynamic-code, or shell tool may enter the product.

## Delivery sequence

1. Create the committed shared baseline before delegating: `pyproject.toml` and
   `uv.lock`; package namespaces and typed cross-cutting contracts; a concise
   project-wiki contract page covering manifest schema, red-status rules, and
   module ownership. Extend node setup/lint/test hooks without removing their
   existing safeguards. Add the initial CI workflow and repository-policy/
   credential checks. Commit this baseline with `fractal commit` so children
   fork identical interfaces.

2. Freeze the API manifest from the source snapshot, not from guessed resource
   names. Include 207 documented G/L/C/U/D rows, 92 individually tagged
   `ambiguous_bulk` rows, and the six documented special routes. Every row gets
   the design-required fields: route, method, request/response fields, filters,
   paging, errors, sensitivity/side effects, cleanup, planned tool name, and
   test references. Use `page`/`pageSize` only; preserve full invoice, bill,
   and daybook-transaction filters; exclude CMS `/documents` and webhooks.

3. Freeze the UI and egress inventories. Seed all documented interface route
   families and an API-parity cross-map as red discovery rows, with no
   unevidenced `not_applicable` result. Include `mit.billy.dk` for browser
   UI/auth, `download.billy.dk` only for a future typed download, lock API use
   to `api.billysbilling.com`, and explicitly deny `api.billy.dk` plus unknown
   destinations. Generate `coverage/status.json` and a human-readable report
   with `complete: false` and accurate red/ambiguous counts.

4. Implement the shared package without domain tool stubs:

   - Pydantic configuration and result/error models, token/keyring resolution,
     selected organisation context, and recursive redaction for credentials,
     cookies, MFA values, and confirmation tickets.
   - Stable Billy error conversion (both documented 401 envelopes map to
     `AUTH_REQUIRED`) and an HTTP client whose immutable base is
     `https://api.billysbilling.com/v2`. Test transports are injectable; noisy
     non-JSON prefixes are stripped before JSON parsing.
   - An in-memory confirmation-ticket store using at least 256 bits of entropy,
     five-minute-or-less expiry, one-time consumption, canonical request and
     expected-state bindings, and optional exact file/destination bindings.
   - A persistent-profile Playwright runtime that is headless-only, has no
     desktop controls, applies the manifest allowlist, denies unknown egress,
     and records no production evidence.
   - A FastMCP stdio entrypoint that registers only fully implemented typed
     `coverage_*` tools. Planned `api_*` and `ui_*` names remain manifest data.

5. Add deterministic unit and contract tests for schema loading and report
   generation, inventory arithmetic, base URL/egress locks, page/pageSize
   construction, known error envelopes, secret redaction, ticket tampering /
   replay / expiry / organisation and file binding, headless browser launch
   settings, and tool registration. Add CI for format, lint, type, unit,
   manifest freshness, dependency audit, and credential/public-artifact scans.
   Do not add mocked results as live evidence.

6. After the baseline commit, delegate only disjoint work that has a frozen
   interface. This is a mandatory split because inventory generation and
   foundation safety work are independently deep. Create focused child nodes
   with explicit permitted routes and file ownership:

   ```text
   fractal node init coverage_inventory --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
     --base=main.billy_complete --scope=coverage,scripts,tests \
     --agent=codex-power --max-depth=0 --max-children=0 --max-descendants=0

   fractal node init shared_foundation --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
     --base=main.billy_complete --scope=src/billy_mcp,tests/unit \
     --agent=codex-power --max-depth=0 --max-children=0 --max-descendants=0
   ```

   Configure each child's `NODE.md` with the cited contract, strict no-stub /
   no-green requirements, and its exact paths. Commit the child configuration
   and start it only after verifying the initial commit and configured limits.
   The root retains `pyproject.toml`, `.github/`, shared scripts, docs/wiki,
   dependency lock, and integration tests to prevent ownership overlap. A later
   Grok child owns headless UI discovery and independent review only after the
   Playwright foundation is merged; it must return a cited brief and never edit
   foundation files.

7. Monitor child radio/status, review each three-dot diff, run the inherited
   tests from a clean archived checkout, and merge only ready work with
   `git merge --no-ff -m "merge <child>" <child>`. Reconcile wiki links and
   coverage generation after merges. Any live/API/UI assertion blocked by the
   missing token or absent test-org path remains visibly red and is reported.

## Phase 0 acceptance checks

- Inventory includes the full official 305-operation snapshot without falsely
  treating ambiguous bulk or the singular organisation sample as implemented.
- Both manifests, egress policy, generated report, and `status.json` exist;
  `status.json.complete` is exactly `false`.
- Server stdio import and `coverage_*` schema calls work, while zero generic or
  planned domain tools are registered.
- Unit/contract/safety checks pass locally without a Billy token; no live,
  vision, or completeness check is represented as passing.
- Browser configuration is bounded and headless, and every tested network path
  is locked to the approved hosts.
- CI has no secrets and the repository scan detects credentials and forbidden
  browser evidence.

## Known blockers carried forward

`BILLY_API_TOKEN` is unavailable, so controlled API qualification, bulk
clarification, undocumented filters, broader errors, and irreversible write
testing cannot advance. The persistent profile can be used only for a
headless, read-only discovery probe once the Playwright runtime is installed;
no successful probe makes an interface row green without DOM assertions,
independent read-back, and a purged-frame Grok review record.
