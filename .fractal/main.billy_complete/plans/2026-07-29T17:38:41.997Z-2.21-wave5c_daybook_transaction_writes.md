# 2.21 Wave-5c daybook transaction writes

## Objective

Promote the cited, current Grok brief at
`.fractal/main.billy_complete/tmp/grok-research.md` into the shared Wave-5c
contract, then implement the six documented singular CUD operations for
`daybookTransactions` and `daybookTransactionLines`. This is an offline-only
API slice: it must add 12 ticketed `api_*` tools while leaving every live, bulk,
special-route, UI, vision, and completeness claim red.

## Contract and boundary

- The official documentation was re-fetched by Grok at ETag
  `hsisik4g9p3603` / MD5 `c2efda0ee4cf9cf200e14910c5fc6996`; it is the cited
  contract for this slice.
- Implement only `POST`, `PUT`, and `DELETE` for the two documented collections
  using singular roots `daybookTransaction` and `daybookTransactionLine`. PUT
  is partial; DELETE has no HTTP body; paths never include a duplicate `/v2`.
- Reuse the one root-owned `ConfirmationStore` and `WriteProtocolService`.
  Every preview must bind its literal `execute_tool_name`; every execute handler
  must pass that same server-owned literal. A wrong executor must fail with
  `CONFIRMATION_MISMATCH` before ticket consumption or HTTP.
- Keep opaque `dict[str, JsonValue]` payloads with Pydantic outer models that
  forbid extras. Do not infer an embedded-lines schema, extra changed-response
  roots, bulk request bodies, webhook behaviour, or live cleanup proof.
- No live API/browser call is authorised for this slice. In particular, the
  unauthenticated empty DELETE responses are not qualification evidence.

## Delegation decision and feasibility

The parent and line resource modules plus their contract suites are disjoint,
substantial product work, so two Codex Power leaves will run in parallel. Root
keeps the shared wiki contract, server registration, generated coverage,
cross-module ticket test, integration, and review orchestration. A Grok review
cannot be independent until the merged root is testable, so it is deferred.

There is no time or cost cap. Root plus two leaves uses three of four available
slots. Each leaf is a childless eight-iteration node and explicitly routed to
`codex-power`; the later reviewer is explicitly routed to `grok`.
