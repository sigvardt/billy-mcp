## Design choices

1. **TDD first.** First product edit is a failing FastMCP unit test. Run it.
   Capture the failure. Then implement.
2. **Compare the live slug to the ticket.** Pass
   `prepared.binding.organization_id` into every action. After the write page
   is open enough to read a URL slug, compare exact stripped strings. Mismatch
   returns `CONFIRMATION_MISMATCH` before fill or click. Missing live slug
   returns `ORGANIZATION_REQUIRED`. Do not invent a new error code. Do not
   call `/user/organizations` or any `/v2/*`.
3. **Independent read-back is a second runtime.** `create_server` already
   builds one write `BrowserRuntime`. Build a second one with a different
   `profile_path` (write profile name plus `-readback`, still under the MCP
   data root, never in git). Pass it into family submitters and the contacts
   actor. `prove_text_on_fresh_page` takes that runtime and calls `start()` on
   it. Same-context `new_page` is illegal for qualification read-back.
4. **Fakes must be two sessions.** Patch `BrowserRuntime.start` by profile
   path, or inject two `FakeBillySession` objects. The write session's
   `readback_page_count()` is not proof. Read-back must start the second
   session.
5. **Wrong-org fake.** Fake page that lands on `org-b` when the ticket bound
   `org-a`. Execute is an error. No fill. No click.
6. **No greening.** Honesty set stays 16. `tool_name` stays on `*_open` tools.
