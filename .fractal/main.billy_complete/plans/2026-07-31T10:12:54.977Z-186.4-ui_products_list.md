## Contract freeze (research103)

### Tool

- **Name:** `ui_products_list`
- **Input:** empty strict model (`extra=forbid`) — no URL, selector, org id,
  filter, credential, or product fields.
- **Success:** non-PII only:
  - `path_class`: literal `/:org_slug/products`
  - `heading`: literal `Produkter`
  - `search_control_visible`: bool for `data-cy=search-button` (or documented
    equivalent observed control; prefer exact research freeze)
  - `shell_markers_present`: bool for ≥1 shared shell marker
    (Overblik / Fakturering / Menu / Produkter) without dumping page text
- **Errors:** `AUTH_REQUIRED` (login signature), `AUTH_INTERACTION_REQUIRED`
  (challenge selectors), `UI_CHANGED` (error shell, wrong path, missing h1 /
  search control when required), `EGRESS_DENIED`, `BILLY_ERROR`.
  Messages must not include org slug, org name, email, password, tokens, or
  product names/prices.
- **Navigation:**
  1. Open persistent MCP profile under fixed egress.
  2. If login signature present → `AUTH_REQUIRED` (callers use auth tools first).
  3. Resolve org slug from session URL or outside-git identity file only.
  4. `page.goto` only `https://mit.billy.dk/{slug}/products`.
  5. Wait for settle (networkidle with timeout fallback / poll loop like invoices).
  6. Classify: path match `^/[^/]+/products$`; h1 exact `Produkter`;
     search control present; reject login signature, challenge, or error markers
     (`Upsedasse`, `Log ind igen`).

### Explicit non-actions

- No click on `Mere`, `show-archived`, search submit, import, or row open.
- No API client calls.
- No product name / SKU / price assertions in success model or tests.
