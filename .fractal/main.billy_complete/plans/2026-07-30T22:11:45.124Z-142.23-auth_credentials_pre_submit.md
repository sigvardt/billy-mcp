# 142.23 Auth credential references and pre-submit login

## Objective

Deliver one offline-only authentication product slice: safe browser credential
references and a typed, fail-closed pre-submit login transition. It must not
submit real credentials, infer post-login UI, select an organisation, bootstrap
an API token, make a residual/bulk request, or alter coverage state.

## Contract and hard boundaries

- `.fractal/main.billy_complete/tmp/grok-research.md` (research92) is the
  required current cited Grok brief. Its official-source fingerprint is ETag
  `wcw4x9hqvu3603` and MD5 `8b94b0135c91fd15fe54ea33e088a4be`; it freezes this
  narrow slice and explicitly leaves live and vision qualification red.
- The approved design and research91/92 permit only the fixed headless
  `https://mit.billy.dk/` login flow. The exact pre-submit signature is the
  `/login` URL without query or fragment; one visible email, password, and
  remember control; and one visible `button[data-cy=login-button]` labelled
  `Log in` or `Log ind`.
- Config and tool models may contain opaque credential-store references or
  environment-variable names only. They must never accept or serialise email,
  password, TOTP, cookie, access token, selector, URL, click instruction, or
  raw browser state. TOTP stays unresolved until a later observed, reviewed
  challenge signature exists.
- Missing credentials return `AUTH_REQUIRED`; signature drift before
  resolution returns `UI_CHANGED`; egress failure returns `EGRESS_DENIED`; and
  unexpected runtime failure is redacted as `BILLY_ERROR`. No unobserved
  challenge is classified as `AUTH_INTERACTION_REQUIRED`.
- All 339 UI rows and API live/vision states remain red. Do not edit coverage
  manifests or status, add generic browser controls, capture browser evidence,
  or use any live credential.

The product slice is one coupled source-and-test change across configuration,
credential resolution, browser runtime, models, FastMCP registration, and test
fakes. It has real implementation depth, so it belongs to one focused
`codex-power` leaf rather than split files that would need to coordinate a
security-sensitive protocol. Independent review must follow the merged code,
so it cannot run concurrently.

## Required proof matrix

- Known signature plus unavailable reference returns `AUTH_REQUIRED` without
  resolver, fill, or click calls.
- Bad route, duplicate/hidden/missing control, or bad label returns
  `UI_CHANGED` before resolving a reference and without fill/click calls.
- Fake resolver and fake page prove resolution happens only after the first
  signature check and a second signature check occurs before any fill/click.
- Tests demonstrate one fixed login target, forced headless Chromium,
  downloads disabled, egress deny-by-default, page closure on every path, and
  redaction of fake secret failures.
- Serialised config, typed inputs, outputs, errors, confirmation state, and
  logs contain references only; optional TOTP is neither resolved nor located.
- No live browser submission, API request, organisation lookup/selection,
  token creation, screen capture, HAR, trace, or test organisation mutation is
  allowed in this slice.

reauthentication transitions, token bootstrap, UI parity, API live testing,
residual/bulk observation, vision review, cleanup qualification, and overall
completeness remain blocked on dedicated non-production material and the
