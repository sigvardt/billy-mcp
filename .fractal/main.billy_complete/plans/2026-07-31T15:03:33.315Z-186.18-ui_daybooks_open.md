## Contract freeze (research117)

### Tool

- **Name:** `ui_daybooks_open`
- **Input:** empty strict model (`extra=forbid`) — no URL, selector, org id,
  daybook id, filter, credential, local file path, digest, destination, or
  create payload.
- **Success:** non-PII only:
  - `path_class`: literal `/:org_slug/daybooks/new` (research117 dual-stable
    empty-editor open). Accept only this product path; do not return bare
    `/daybooks` as success.
  - `heading`: empty string allowed (editor has no h1 in freeze); do **not**
    require a non-empty h1.
  - `editor_markers_present`: bool true when stable editor chrome is present:
    all of **Opret ny kassekladde**, **Tilføj kassekladdelinje**, and
    **Ingen postering valgt** observed (text visibility), without dumping page
    text into the tool result.
  - `shell_markers_present`: bool for ≥1 shared shell marker
    (Overblik / Fakturering / Fakturaer / Udgifter / Menu / Bank / Bilag /
    Regnskab / Bogføring / Rapporter) without dumping page text
- **Errors:** `AUTH_REQUIRED` (login signature), `AUTH_INTERACTION_REQUIRED`
  (challenge selectors), `UI_CHANGED` (Upsedasse/error shell, bare `/daybooks`
  only, wrong path class, missing editor markers, classification failure),
  `EGRESS_DENIED`, `BILLY_ERROR`.
  Messages must not include org slug, org name, email, password, tokens, or
  customer PII.
- **Navigation:**
  1. Open MCP profile under fixed egress (`coverage/browser_egress.yaml`).
  2. If login signature present → `AUTH_REQUIRED` (callers use auth tools first).
  3. Resolve org slug from session URL or outside-git identity file only.
  4. Direct goto `https://mit.billy.dk/{org_slug}/daybooks/new` (research117
     freeze target). Do **not** use bare `/daybooks` as the success target
     (known Upsedasse in dual sessions).
  5. Classify path with regex equivalent to
     `^/[^/]+/daybooks/new$` (optional query params allowed if Billy adds any;
     path class remains `/:org_slug/daybooks/new`).
  6. Signature: path class match + editor markers present + not login + not
     Upsedasse/error shell + shell markers. Do **not** require tables or h1.
  7. Reject bare `daybooks`, soft aliases (`kassekladde`, `daybook`, …), and
     transactions list as `UI_CHANGED` for this tool.
- **Hard bans:** never click Opret ny kassekladde / Tilføj kassekladdelinje /
  Bogfør / Godkend / Slet / Rediger / Ny postering; never fill editor line
  fields; never call invent API tools; never treat bare `/daybooks` or
  Posteringer list as success for this tool.
- **Session:** no API token; no screenshot persistence in production tool path;
  live test captures frames only outside git for vision then purges.
