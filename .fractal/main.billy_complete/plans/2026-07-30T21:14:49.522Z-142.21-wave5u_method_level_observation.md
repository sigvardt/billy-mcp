# 142.21 Wave-5u method-level live observation

## Decision

Research90 is the current cited contract handoff: Billy's official API page is
byte-identical to research88/89 and unauthenticated `OPTIONS` is now proven
non-discriminative.  It returns the same 204/full-CORS-method response for
known closed and auth-gated candidate routes.  The existing Wave-5t
`OPTIONS`-only harness must therefore never be used to infer support.

The next bounded deliverable is infrastructure only: a method-level,
fail-closed observation runner.  It cannot register residual or bulk tools,
alter API/UI coverage fields, create durable test data, or turn a response into
live qualification.  `coverage/status.json` must remain 184/184/0/0 and
`complete: false`.

## Decomposition and ownership

The work has distinct research, implementation, and independent-audit phases,
so it will use focused sequential leaves after the parent commits the shared
research and this plan.  This avoids a child starting from uncommitted evidence
and preserves a clean review tip.

1. `wave5u_probe_contract` — **Grok** owns one cited project-wiki brief that
   narrows every safe, non-persistent method-observation request shape.  It may
   change only `wiki/wave5u_method_probe_contract.md`.  Its brief must explain
   why every static POST/PUT/DELETE input cannot create, update, or delete a
   Billy record; if an input cannot be justified, the candidate stays blocked
   and makes no network call.  It must keep the current official-doc citation,
   error-envelope evidence, and all red coverage intact.

2. `wave5u_probe_implementation` — **Codex Power** owns only
   `src/billy_mcp/live_probe.py`, `scripts/run_live_probe.py`,
   `tests/unit/test_live_probe.py`, and `tests/live/test_live_probe.py`.  It
   consumes the frozen Grok brief and implements no MCP tool.  It must replace
   `OPTIONS` with the candidate's static real method only after token,
   matching dedicated-non-production-org, and owner-only-outside-repository
   evidence gates pass.  Observations retain only candidate id, candidate
   method, static route, status, and an optional top-level `errorCode`; no
   token, response body, customer value, or raw trace may be written.

3. `wave5u_probe_review` — **Grok** owns only
   `wiki/wave5u_method_probe_independent_review.md`, reviewing the merged
   implementation tip against research90 and the contract brief.  A Grok
   authentication/quota failure before edits is retried as the exact review
   with Codex Power as required by routing policy, but that fallback cannot
   satisfy the mandatory Grok-review gate or turn this infrastructure green.

The parent owns baseline commits, clean-diff review, merges, test execution,
coverage checks, and any follow-up fixes.  Leaves must not merge child seed
trees, `tmp/`, credentials, browser evidence, or generated raw captures.  A
child with a project diff beyond its declared ownership is held, as was the
contaminated Wave-5t UI/auth fallback branch.

1. Verify `wiki/wave_fives_residual_specials_research.md` and node memory
   accurately preserve research90; run wiki lint and preserve its explicit
   fail-closed wording.  Commit this plan and the research record before any
   child initialisation.

2. Initialise and launch the research leaf from that committed baseline:

   ```sh
   fractal node init wave5u_probe_contract --path=. --agent=grok \
     --title='Wave-5u safe method observation contract' \
     --scope=wiki --max-depth=0 --max-children=0 --max-descendants=0
   fractal node start main.billy_complete.wave5u_probe_contract
   ```

   If it fails before edits because Grok authentication, quota, or a rate limit
   is unavailable, rerun the same bounded research mission with
   `--agent=codex-power`; record that it is a fallback and keep the Grok research
   gate unresolved.

3. Review the research branch's three-dot diff and accept only its declared
   wiki page after the cited contract is complete.  Commit that shared contract,
   then initialise the implementation leaf:

   ```sh
   fractal node init wave5u_probe_implementation --path=. --agent=codex-power \
     --title='Wave-5u method-level probe implementation' \
     --scope=src/billy_mcp,tests/unit,tests/live,scripts \
     --max-depth=0 --max-children=0 --max-descendants=0
   fractal node start main.billy_complete.wave5u_probe_implementation
   ```

4. Require implementation tests for: zero network traffic without a token;
   organisation absence/mismatch before networking; immutable Billy base URL;
   static route/query/body selection by candidate kind; no `OPTIONS` request;
   owner-only evidence outside the repository; response sanitisation; transport
   failures; meta-only 200 responses still unqualified; no mutation or coverage
   update from the harness; and the opt-in live runner's safe skip path.  Run
   the focused tests from a clean archive before merging a source-only diff.

5. Launch the independent review leaf from the merged implementation:

   ```sh
   fractal node init wave5u_probe_review --path=. --agent=grok \
     --title='Wave-5u method probe independent review' \
     --scope=wiki --max-depth=0 --max-children=0 --max-descendants=0
   fractal node start main.billy_complete.wave5u_probe_review
   ```

   Address every review finding, rerun focused tests plus formatter, Ruff,
   Pyright, inventory/policy checks, and the normal non-live suite.  Do not run
   a token-backed live probe without an explicitly matched dedicated
   non-production organisation.  A missing credential must remain a successful
   zero-network skip, not a mock live result.

6. Reconcile the wiki index after each accepted wiki diff.  Confirm all raw
   evidence remains owner-only outside the repository, no coverage flag changed,
   and no residual/bulk/API/UI tool was added.  Report the infrastructure result
   as incomplete until a dedicated test organisation supplies real method
   evidence, cleanup proof, and a later product contract.
