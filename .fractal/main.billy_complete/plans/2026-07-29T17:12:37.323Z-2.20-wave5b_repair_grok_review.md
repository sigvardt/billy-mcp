# 2.20 Wave-5b repair independent Grok review

## Objective

Obtain a fresh, independent Grok verdict for the committed Wave-5b P1/P2
repair at `a2a0996`. This is the gate for the already-researched Wave-5c
daybook-transaction write cohort; no Wave-5c product change is authorized
until the verdict is an explicit ACCEPT.

## Inputs and invariants

- Review target: `a2a0996` against the prior integrated Wave-5b baseline
  `920ceab` and the canonical record
  `wiki/wave_fiveb_product_independent_review.md`.
- Contract: `docs/superpowers/specs/2026-07-28-billy-mcp-complete-design.md`,
  the current official Billy API documentation, and
  `wiki/wave_fiveb_ticketed_writes_contract.md`.
- The refreshed cited Wave-5c brief is research-only. Its six rows, all UI
  rows, live state, bulk rows, specials, and `complete` remain unchanged.
- Review is read-only against product code. A durable review report is the only
  project deliverable; it must name its exact reviewed commit and verdict.

## Delegation decision

Spawn one focused `grok` leaf. The mandatory independent review needs both a
clean context and Grok ownership, so it cannot be performed or accepted by the
root's Codex Power implementation lane. No parallel implementation leaf is
appropriate because the acceptance gate blocks Wave-5c.

## Execution

1. Launch the review leaf from the committed root baseline with the following
   commands (the root's uncommitted research records are intentionally excluded
   from the review target):

   ```sh
   reviewer_worktree="$(fractal node init wave5b_repair_grok_review \
     --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
     --agent=grok --max-iters=3 --timeout=2h --iter-timeout=40m \
     --step-timeout=20m --max-depth=0 --max-children=0 --max-descendants=0 \
     | sed -n 's/^Initialized //p')"
   # Configure the child NODE.md, then commit from "$reviewer_worktree".
   (cd "$reviewer_worktree" && fractal commit "configure wave5b_repair_grok_review" --init)
   fractal node start main.billy_complete.wave5b_repair_grok_review
   ```

   Configure `wave5b_repair_grok_review` with explicit `--agent=grok`, no
   descendants, and exclusive ownership of
   `wiki/wave_fiveb_repair_independent_review.md` plus its generated wiki index
   row. Its completion condition is a Grok-authored ACCEPT or REJECT report;
   rejection is a successful review deliverable, not a stranded node.
2. The child must inspect only committed bytes from `a2a0996` in a clean
   archive, re-check the current official documentation fingerprint, and
   independently exercise the P1/P2 regressions: server-owned executor identity
   on all 24 handlers, cross-module mismatch before HTTP/consumption, replay
   and expiry preservation, and pruning of terminal/expired state. It must
   record the commands and result counts without secrets or raw sensitive data.
3. The child must issue one explicit result:
   - **ACCEPT:** evidence that the repair closes P1/P2 while preserving the
     fail-closed qualification state.
   - **REJECT:** actionable findings with file/line or test-path evidence and
     no Wave-5c authorization.
4. While the review runs, preserve the refreshed Wave-5c research/memory plan
   for this iteration and make no product, inventory, or coverage edits.
5. On a later preparation pass, merge the committed Grok report if it is
   merge-ready, reconcile the wiki index, and act on the verdict. Only an
   ACCEPT permits promotion of the Wave-5c brief to a shared contract freeze
   and subsequent Codex Power implementation leaves.

## Verification and stop conditions

- Before launch, verify the parent worktree is clean except for this
  iteration's research/memory/plan records, and verify the reviewer starts from
  the committed `a2a0996` source baseline.
- Do not relabel the earlier Codex fallback as a Grok audit.
- If Grok fails before changing files because of authentication, quota, or a
  rate limit, retry this same review with the permitted Codex Power fallback and
  retain Wave-5c as blocked; never treat that fallback as the missing Grok gate.

## Post-Mortem

The configured Grok leaf failed before edits because the Grok runtime was not
signed in. Per routing policy, a Codex Power fallback was launched and then
closed when the root independent-review step supplied the authoritative Grok
record. That record accepts the repaired Wave-5b offline product at `a2a0996`;
the root lint, policy, coverage, and 650-test non-live suite pass. Wave-5c is
not yet implemented or green: its cited research must first be promoted to a
shared freeze.
