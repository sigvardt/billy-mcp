# 2.12 Wave 5a multi-root mapping and ticketed writes

## Objective

Deliver the first ticketed API-write cohort without advancing any live, bulk,
interface, vision, special-route, or completion state.  The Cohort consists of
the documented singular create/update/delete operations for products,
productPrices, contacts, contactPersons, and daybooks: fifteen inventory rows
and thirty paired preview/execute tools.

The current cited Grok brief is
`.fractal/main.billy_complete/tmp/grok-research.md`.  It re-fetched the official
documentation at ETag `hsisik4g9p3603` / MD5
`c2efda0ee4cf9cf200e14910c5fc6996`, which matches the frozen inventory.  Its
contract is also recorded in `wiki/wave_five_ticketed_writes_contract.md`.

## Decision and dependency order

The work is separable and must be delegated.  Five Codex Power product leaves
have non-overlapping owned files, followed by one Codex Power registration leaf
and an independent Grok audit.  A small protocol mapping leaf is first because
the accepted foundation review requires product embed creates to preserve every
documented changed plural response root; the present protocol retains only the
operation's primary plural root.

The runtime has four agent slots including this manager, so launch only three
children at once.  The initial active tranche is protocol mapping, contacts,
and contact persons.  After the protocol leaf is merged, launch catalog writes;
after either initial resource leaf is merged, launch daybook writes.  This keeps
three active leaves while preserving the catalog dependency.

All child nodes are childless `--agent=codex-power` leaves with
`--max-depth=0 --max-children=0 --max-descendants=0`; their `NODE.md` must state
the exact file ownership below.  Create nodes serially from the committed
foundation baseline, configure and commit each seed, then start them in separate
commands.  Do not use a different model after an edit has begun.

Every resource leaf must:

- Declare typed, `extra="forbid"` outer preview inputs, execute input, and
  success/error outputs.  Singular-root payloads may be opaque
  `dict[str, JsonValue]`; do not invent unresolved offline field validators.
- Register exactly `api_<area>_<create|update|delete>_<preview|execute>` tools
  through a `register_*_write_tools(server, client, write_protocol)` helper.
- Use `WriteOperationSpec` and `WriteProtocolService` only: `POST`/`PUT` bind
  exact `{singularRoot: payload}` JSON; delete binds `{id}` but sends no body;
  IDs are non-empty and the shared service path-escapes them; no write retry.
- Test preview has zero writes, execution uses only `WriteExecuteInput`, exact
  path/method/body, missing-token `AUTH_REQUIRED`, 401/404 propagation, replay
  and expiry, and optional `meta.deletedRecords`.  Catalog tests additionally
  prove all declared response roots survive a product-with-prices fixture.
- Use only `MockTransport`/existing local doubles.  Do not make a Billy mutation,
  change coverage, server, client, auth, UI, browser, specials, or bulk code;
  do not log tickets, API tokens, emails, phones, or registration values.

The current official-doc boundaries are fixed: create `POST /v2/{collection}`
with roots `product`, `productPrice`, `contact`, `contactPerson`, or `daybook`;
update is singular `PUT /v2/{collection}/{id}`; delete is bodyless singular
`DELETE`.  Relative client paths omit `/v2`.  The unauthenticated DELETE 200 is
not cleanup, result-shape, or live-test evidence.  Product `prices[]` is an
embedded create path, not a bulk contract.  Contact `paymentTermsDays`,
contact-person name/email XOR, and all bulk shapes remain unresolved for live
qualification.

   from a clean `git archive` checkout.  Reject scope violations, generic tools,

   `--agent=codex-power` `wave5a_registration` leaf.  It owns server registration
   and its exact tests plus the fifteen inventory-evidence updates and generated
   coverage artifacts.  It must instantiate one process-volatile
   `ConfirmationStore` and one `WriteProtocolService`, register all thirty
   tools, prove 124 `api_*` plus two `coverage_*` tools, and set only those
   fifteen rows' `implemented` and `contract_tested` fields true.  It leaves
   `live_tested` and `complete` false.
3. Run the repository formatter, Ruff, Pyright, non-live suite, coverage
   generator/checker, policy check, and credential scan from clean committed
   bytes.  Full mode is expected to remain fail-closed because live, UI, bulk,
   specials, and remaining writes are red; it is not a qualification pass.
4. Create a fresh childless `--agent=grok` `wave5a_independent_review` leaf
   after the registration merge.  It owns only a new shared-wiki review record,
   rechecks current official documentation and the integrated diff, and reports
   cited required findings.  Fix every required finding before the next cohort.
