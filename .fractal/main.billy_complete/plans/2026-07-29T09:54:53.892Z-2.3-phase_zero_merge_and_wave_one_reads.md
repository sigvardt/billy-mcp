# 2.3 Phase 0 merge and Wave 1 read lanes

## Objective

Land the reviewed Phase 0 inventory and foundation hardening without making a
completeness claim, then create a committed, conflict-free baseline for the
first research-backed API-read wave. The current Grok brief is the contract
source; credentials are absent, so every affected `live_tested` flag stays
false and full qualification must fail closed.

## Evidence and constraints

- Cited official evidence is in `.fractal/main.billy_complete/tmp/grok-research.md`:
  fixed API host, `X-Access-Token`, relative `/v2` paths, global paging and
  list-query limits, the selected Wave 1 routes, and the absence of a bulk
  contract.
- Child `coverage_inventory` commit `b71bb79` provides the 305 API / 339 UI
  red inventory, corrected multipart file alias and `bankLineMatch`, and real

- Child `foundation_hardening` commit `cf07007` rejects duplicate `/v2` paths,

- Preserve the root research and memory edits already in the worktree; update
  them only to describe merged facts. Never retain browser frames, tokens, or
  non-production business data.

## Execution plan

1. Review both completed child branches from clean committed bytes: inspect
   three-dot diffs and ownership boundaries, run `git diff --check`, archive
   each branch, and run its focused tests plus the coverage checker modes. Do
   not merge if the full mode soft-passes a red row or a manifest claims green
   status.
2. Merge approved branches with labelled no-fast-forward commits in this order:
   `main.billy_complete.coverage_inventory`, then
   `main.billy_complete.foundation_hardening`. Reconcile generated wiki indexes
   and the root research/memory edits, check `coverage/status.json` remains
   `complete: false`, and prove the full test command exits non-zero because
   rows are incomplete rather than because a checker option is ignored.
3. Commit the integration baseline before spawning implementation workers. Root
   owns `server.py`, shared Pydantic/read-query contracts, coverage manifests,
   top-level package wiring, CI/scripts, and the Wave 1 shared contract note.
   Establish a real extension point only if it supports actual tools; do not
   register placeholders or mutate coverage state in advance.
4. Spawn four disjoint Codex Power leaves from that committed baseline, each
   with `--agent=codex-power`, `--base=main.billy_complete`, inherited scripts,
   skills, and config, and `--scope=src/billy_mcp/api,tests/api`. Their NODE
   contracts must give the exact file ownership below and prohibit edits to
   server wiring, shared models, coverage manifests, and other workers' files.

   - `wave1_bootstrap_reads`: `bootstrap_reads.py` and
     `test_bootstrap_reads.py`; `api_user_get`,
     `api_user_list_organizations`, `api_organizations_get`, and
     `api_organizations_list`.
   - `wave1_reference_reads`: `reference_reads.py` and
     `test_reference_reads.py`; currencies, countries, and locales get/list.
   - `wave1_catalog_reads`: `catalog_reads.py` and
     `test_catalog_reads.py`; products and product-prices get/list.
   - `wave1_contact_reads`: `contact_reads.py` and
     `test_contact_reads.py`; contacts get/list.

   Each worker implements real Pydantic input/success/error outputs, uses the
   locked client only, allows only documented page/pageSize/include/sort query
   parameters, maps singular/list roots and paging, and supplies mock-transport
   contract tests. Root sets only its real rows `implemented` and
   `contract_tested` after clean-byte integration verification. No worker may
   set `live_tested`, add filters, writes, bulk operations, generic controls,
   or browser workflows.
5. While workers run, root reviews their radio reports, retains integration
   messages in the saved queue, and prepares the real server registration after
   each tool module is reviewed. Merge each completed branch only after a
   clean-archive test and root integration test; then update the inventory and
   run the full offline suite.

## Delegation decision

This is deliberately manager-shaped. The four read areas are contractually
independent but all depend on the same reviewed Phase 0 baseline, so spawning
before that merge would fork stale client/coverage interfaces. Grok research is
already cited and current, so no duplicate research child is warranted. Codex
Power owns all implementation, test, and commit work.

## Acceptance for this iteration

- Both completed Phase 0 branches are either merged after clean-byte validation
  or left unmerged with a concrete, evidenced defect.
- The root reports coverage as generated and incomplete, and full mode fails
  closed for incomplete evidence.
- Any spawned worker has a committed baseline, exact non-overlapping file
  ownership, and the cited Wave 1 contract in its NODE instructions.
- No API/UI/auth stub, live claim, secret, or raw browser evidence is added.
