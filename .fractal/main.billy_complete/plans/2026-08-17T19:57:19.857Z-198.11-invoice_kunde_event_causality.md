## Design choices

1. **TDD first (`728BD2E4`).** First product edit is a failing unit
   fixture. Current live tagged-trace dump fails
   `kunde_event_missing_keys`. Run it. Capture the failure. Then
   implement. Do not reuse `REQUIRED_KUNDE_TRACE_KEYS` or the
   8EFD0EAD opener-missing fixture as this fixture.
2. **Honesty-16 stays red.** Confirm the coverage gate still
   length 16 before any other edit.
3. **Keys are allowlisted tokens, counts, and 16-char hex
   fingerprints.** Never store message text, stack arguments,
   bodies, URLs, IDs, tag text, or typed keys in git.
4. **Listeners first.** Page request/console/pageerror plus a
   document init script for field events attach **before**
   `goto /invoices/new`. Count only events whose target
   `name_token` is `contact`.
5. **Phase-scoped.** `event_counts` and `console_delta` are that
   phase only, not running totals. Snapshot at rest, after click,
   and after type.
6. **`error_class` allowlist.** `TypeError`, `ReferenceError`,
   `SyntaxError`, `RangeError`, `URIError`, `EvalError`,
   `EmberError`, `other`. `source_class`: `inline`, `same_origin`,
   `worker`, `unknown`. `phase`: `at_rest`, `after_click`,
   `after_type`. Cap `errors` at 8.
7. **`fingerprint`.** 16-char hex of allowlisted class + source
   class + scrubbed message shape. Raw messages may land only
   under `~/.local/share/billy-mcp/` and are purged after review.
8. **Instrumented click + type are allowed once.** Center click
   the proved `input[name=contact]`. Then type the exact FastMCP
   tag with the existing sequential path. This is not an
   `8EFD0EAD` repeat: the new listeners and keys are the product.
9. **Rest pageerror.** `pageerror_unrelated_at_rest=true` only
   when that fingerprint is present at rest and the `pageerror`
   delta after click and after type is 0. Then keep going on
   event counts. Do not treat the rest error as a bind.
10. **Named next action.** True only when the new dump shows a
    concrete wrong sequence (`keydown=0` and `input=0` after type)
    or one named interaction (`input>0` and `change=0` with no
    contacts request). Cumulative script-count rise alone is not
    a named action. Implement at most one named fix. Otherwise
    `UI_CHANGED`.
11. **Cleanup.** Delete the tagged customer through FastMCP in a
    fresh session. Prove absence. Do not leave `MCP-UI-INV-*`
    contacts.
12. **Do not remap.** Preview `tool_name` waits for a later slice
    after independent accept + purge.
13. **Vision.** Live test may write `author=live_test` and
    `reviewer_verdict=pending_review` only. Field shot and
    owner-only message file live under `~/.local/share/billy-mcp/`
    and are purged after review.
