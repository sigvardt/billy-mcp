# 2.11 Wave 5a write foundation integration and fan-out

## Objective

Integrate the shared ticketed-write protocol only after its focused Codex Power
leaf has committed a clean, contract-conforming delivery. Then fan out the
four disjoint Wave-5a resource modules. This remains an offline-only slice:
the fifteen selected inventory rows may later gain `implemented` and
`contract_tested` evidence, while live, UI, vision, bulk, specials, and
completion remain red.

## Delegation decision

The active `wave5_write_foundation` Codex Power leaf exclusively owns the
shared protocol and its unit tests. Starting resource leaves before that module
is merged would create an unstable interface, so this turn manages that
dependency rather than duplicating product work. Once the foundation is
verified and merged, the catalogue, contact, contact-person, and daybook
write modules are independent enough to run concurrently; each will be a
childless `codex-power` leaf with exclusive ownership of exactly one product
file and one focused test file. The later independent review remains a fresh
`grok` leaf after root integration.
