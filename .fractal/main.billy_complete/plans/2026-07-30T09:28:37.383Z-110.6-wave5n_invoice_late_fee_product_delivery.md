## Delegation decision

This is a bounded repository implementation with disjoint files and a cited
Grok brief already committed before the child launches. It must therefore be a
focused `codex-power` leaf, not root implementation. The independent review
depends on that leaf's committed product and is intentionally sequential.

### Stage 1 — Codex Power product leaf

1. Checkpoint the research state and both Wave-5n plans on root before the
   child is initialized, so its branch includes the accepted contract evidence.
2. Create and configure the leaf using the explicit routing command:

   ```bash
   fractal node init wave5n_invoice_late_fee_product \
     --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
     --agent=codex-power --max-cost=320 --max-iter-cost=80 --max-iters=8 \
     --step-timeout=20m --max-depth=0 --max-children=0 --max-descendants=0
   ```

3. Its `NODE.md` gives it exclusive ownership of:

   - `src/billy_mcp/api/invoice_late_fee_writes.py`
   - `tests/api/test_invoice_late_fee_writes.py`
   - narrowly necessary registration in `src/billy_mcp/server.py`
   - the two invoice-late-fee rows in `coverage/api_v2_manifest.yaml`
   - generated coverage state plus the narrow generator/coverage and registry
     tests required to make that state truthful (`coverage/status.json`,
     `src/billy_mcp/coverage_generator.py`,
     `tests/coverage/test_coverage_inventory.py`, and
     `tests/unit/test_coverage_server.py` only if needed for the four-tool
     registry count).

4. Require a strict clone of `contact_balance_payment_writes.py`, with only
   the frozen resource nouns, roots, and path changed. The inner
   `invoiceLateFee` value stays an opaque JSON map; update's inner `id`, if
   supplied, must equal the route `id`. Preview is mutation-free and execute
   accepts only the confirmation ticket through the shared write protocol.
5. Require tests for strict outer schemas, unknown inner values, matching and
   mismatched update IDs, mutation-free previews, canonical binding, escaped
   path, exact one-write request, plural-root-only mapping, malformed/missing
   root rejection, tamper/wrong-executor/expiry/replay, typed HTTP errors,
   absent token, and no retry. Validate formatting, Ruff, Pyright, focused
   API/coverage/registry tests, and the repository safety checks before commit.
6. After genuine tests only, green `create` and `update` for
   `implemented` and `contract_tested`; revise create cleanup to
   `live non-production cleanup strategy unqualified; singular DELETE is unsupported`.
   The only acceptable count change is 174 implemented and contract-tested
   rows and 254 `api_*` tools. Live and vision remain zero and
   `complete: false`.
7. The leaf must not implement DELETE, either bulk operation, a webhook,
   payload-field schema, a cleanup mutation, live/API browser testing, or
   interface work. It commits a clean, passing product result and reports it
   via its outbox without claiming independent product acceptance.

### Stage 2 — root integration and independent review

1. Inspect the completed leaf from a clean archive and with a three-dot diff;
   verify its ownership boundary, generated coverage truthfulness, and focused
   tests before merging it with a labelled no-fast-forward merge. Remove only
   its merged node seed artifacts, then reconcile the wiki index if the child
   created durable documentation.
2. Run the root non-live suite and verify the 254/174/0/0/false status before
   opening product review.
3. Spawn a separate Grok reviewer only after the merged source exists. It owns
   a cited, non-sensitive `wiki/wave_fiven_product_independent_review.md`
   verdict and reviews current official documentation plus committed bytes; it
   must expressly keep live, UI, vision, delete, bulk, and completeness red.
   If Grok fails before editing due to authentication, quota, or rate limiting,
   retry the full review with a `codex-power` fallback reviewer; never switch
   reviewers after a review record has been edited.
4. Merge an ACCEPT review only after root verifies the cited scope. A rejection
   returns work to a new, focused Codex Power repair leaf; no coverage result is
   softened to pass the review.

## Feasibility and stop conditions

The node budget is uncapped; the leaf's 320 USD cap includes solve, test,
commit, memory fold, and finish reserve. There are no active children and no
source-file overlap. Stage 2 is deliberately deferred until Stage 1 is merged,
so it cannot review uncommitted bytes. This plan does not authorise Wave-5o
`invoiceReminders`, the 92 ambiguous bulk entries, credentials, or browser
qualification.
