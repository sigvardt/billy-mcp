## Delegation decision

Do not create another child during this plan. The active `codex-power` leaf
owns one coupled security-sensitive source and test change. A Grok product
review depends on its merged, clean-archive bytes, so it cannot usefully run in
parallel. The next child, if the product leaf passes the parent audit, will be a
dedicated `grok` independent-review leaf with project-wiki-only ownership and
an explicit `--agent=grok` route.

## Execution sequence

1. Keep the active leaf on its bounded contract: opaque references only;
   signature-first validation; resolver after validation; recheck before
   fill/click; forced headless browser; no real credential submission, generic
   browser tools, coverage edits, or residual/bulk traffic.
2. When a child implementation commit appears, audit its committed bytes from
   a clean `git archive`. Reject out-of-scope files, secret-bearing models,
   fixtures, logs, outputs, generic navigation controls, title-language
   assumptions, CAPTCHA-config challenge classification, live submission, and
   any coverage modification.
3. If accepted, merge with `--no-ff` and run the focused auth tests, formatting,
   Ruff, Pyright, non-live suite, coverage/repository policy checks, dependency
   audit, and credential scan. Confirm the generated status remains
   `complete: false` with API live and UI/vision rows red.
4. Only after that audit, create a scoped `grok` review child to compare the
   merged source and test evidence with research92/93 and record a
   non-sensitive independent-review verdict in the project wiki. If that child
   fails before edits due to authentication, quota, or rate limiting, retry the
   full review with `--agent=codex-power` and record it as supplemental rather
   than a replacement for the required Grok gate.
5. Route any review defect to a new `codex-power` repair leaf, then repeat the
   Grok review. Do not merge or green coverage based on planning, research, or
   mocked/live-absent evidence.

The planned work is complete only when the research93 promotion is committed,
the product leaf has either been safely merged and independently reviewed or
has been explicitly redirected for a concrete defect, and all coverage remains
honestly incomplete pending dedicated non-production credentials and tested UI
