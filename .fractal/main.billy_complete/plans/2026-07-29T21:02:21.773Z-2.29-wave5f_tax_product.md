## Delegation decision

This is one cohesive parent/child write module with shared registry and coverage
effects.  Splitting it would create conflicting ownership of `tax_writes.py`,
the server registration, and the shared tool-count assertion.  The cited Grok
brief explicitly recommends one focused Codex Power product child, so root will
commit the research-plan baseline and then initialise this leaf:

```bash
fractal node init wave5f_tax_product --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete --agent=codex-power --base=main.billy_complete --scope=src/billy_mcp,tests/api,tests/unit,coverage --max-depth=0 --max-children=0 --max-descendants=0
```

The child receives exact file ownership in its `NODE.md`: create
`src/billy_mcp/api/tax_writes.py` and `tests/api/test_tax_writes.py`; edit only
the tax-write import/registration in `src/billy_mcp/server.py`, the Wave-5f
registry expectation in `tests/unit/test_coverage_server.py`, any necessary
tax cross-executor test, and the six corresponding generated coverage rows.
It must not edit the frozen contract, change unrelated API/UI rows, or launch a
browser/live write.  A Grok product reviewer cannot begin in parallel because
it must assess the exact integrated product commit.
