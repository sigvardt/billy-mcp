## Delegation decision

The implementation has two independent, disjoint modules with their own
contract suites, so it warrants two Codex Power leaf nodes. Root retains every
shared registration, cross-module test, coverage, and generated-artifact path
to prevent concurrent edits to shared files.

| `wave5e_bill_line_writes` | `src/billy_mcp/api/bill_line_writes.py`, `tests/api/test_bill_line_writes.py` | Six typed ticketed bill-line tools and local contract tests, including present/absent optional `bills` response roots. |

1. Commit this plan and the research-state handoff after repository checks so
   both leaves fork the accepted immutable baseline.
2. Initialize and configure `wave5e_bill_writes` with `--agent=codex-power`,
   a leaf-only depth/children/descendants limit, and explicit file ownership in
   its `NODE.md`. It clones the invoice-parent shape only: `bill` root,
   `bills` response root, `/bills`, and no additional response root.
3. Initialize and configure `wave5e_bill_line_writes` equivalently. It clones
   the invoice-line shape only: `billLine` root, `billLines` response root,

   green coverage or claim product acceptance.
5. Root reviews clean archived child artifacts, selectively no-ff merges their
   two owned files without importing child seed state, registers both modules,
   adds bidirectional bill-to-line executor mismatch tests, adds six coverage
   evidence mappings, regenerates coverage, and proves 178 `api_*` tools / 136
   offline implemented and contract-tested rows / live 0 / complete false.
6. Run root formatter, Ruff, Pyright, non-live suite, coverage generation and
   safety checks. Request a separate Grok product review only after the exact
   root integration commit is available; that review remains required before a
