# 110.13 Wave-5p organizations product delivery

## Decision

Research69, the Wave-5p freeze contract, and its independent Grok ACCEPT now
authorize one tightly coupled offline product slice: organizations create and
update. The source, focused tests, server registration, and two inventory rows
must stay with one implementation leaf because they share the exact ticketed
write contract. A separate Grok product review remains a strict after-merge
gate and cannot run until the implementation is on root.

The work is separable from parent orchestration and has enough depth for a leaf,
so use a dedicated Codex Power child. No parallel reviewer is started early,
because it would lack the committed product surface to review.

## Preconditions to land before spawning

1. Preserve the generated Research69 plan and the refreshed private state in a
   clean root commit. The scratch brief remains owner-only and is never staged.
2. Recheck the root baseline is clean, run the existing non-live checks, then
   initialize the child from that commit. The child must rely on the committed
   contract pages `wiki/wave_fivep_ticketed_writes_contract.md`,
   `wiki/wave_fivep_freeze_independent_review.md`, and
   `wiki/wave_fivep_product_ready_research_independent_review.md`; its NODE.md
   will restate the cited Research69 facts needed for implementation.

## Product leaf

Run from the root worktree after the prerequisite commit:

```text
fractal node init wave5p_organizations_product --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete --agent=codex-power --title='Wave-5p organizations product' --max-cost=320 --max-iter-cost=80 --max-iters=10 --step-timeout=20m --max-depth=0 --max-children=0 --max-descendants=0
```

Give the leaf exclusive ownership of:

- `src/billy_mcp/api/organization_writes.py`
- `tests/api/test_organization_writes.py`
- the minimal registration import/call in `src/billy_mcp/server.py`
- the two organizations create/update rows and test-reference mapping in
  `coverage/api_v2_manifest.yaml` and `scripts/generate_coverage_report.py`
- its own node seed, plans, and memory.

The leaf must implement only these tools:

| Operation | Preview | Execute | HTTP path | Body root | Required response root |
| --- | --- | --- | --- | --- | --- |
| Create | `api_organizations_create_preview` | `api_organizations_create_execute` | `POST /organizations` | `organization` | `organizations` |
| Update | `api_organizations_update_preview` | `api_organizations_update_execute` | `PUT /organizations/:id` | `organization` | `organizations` |

It must follow the accepted `invoice_late_fee_writes.py` pattern: strict flat
outer Pydantic inputs, opaque `dict[str, JsonValue]` inner maps, ticket-only
execute, a five-minute single-use ticket bound to exact executor/request/target,
one non-retried write, only the required `organizations` response root, and
path/body id equality when the update inner map contains `id`. It must preserve
existing subscription-card redaction, reject undeclared outer fields, and avoid
generic transport, browser, webhook, delete, bulk, UI, live, or vision work.

The contract tests must prove registration/schema shape, mutation-free preview,
canonical request/effect, URL escaping, one-write/no-retry, response-root
rejection, auth/error mapping, tamper/wrong-executor/expiry/replay handling,
and coverage/registry honesty. They must leave `live_tested` and
`vision_verified` false. Greening is allowed only after those tests pass:

- `api.organizations.create` cleanup must become exactly `live non-production
  cleanup strategy unqualified; singular DELETE is unsupported`.
- `api.organizations.update` keeps unproven restore wording.
- both bulk rows remain empty-tool `ambiguous_bulk` red; no delete row appears.

## Integration and review sequence

1. Monitor the child and inspect its committed diff and focused/full non-live
   test evidence. Merge only a clean, contract-faithful completion using the
   labelled no-fast-forward merge, reconcile/lint the project wiki if changed,
   and independently regenerate coverage. Expected offline count is 177;
   completeness remains false.
2. Then create a separate `--agent=grok` independent product-review leaf with
   wiki-only ownership. It must independently verify current official docs,
   the 401/405 method gates, exact four-tool surface, test evidence, redaction,
   inventory change, coverage honesty, and every exclusion. It may not claim
   live, UI, vision, bulk, delete cleanup, or completeness.
3. Merge an explicit review verdict, update durable state, and continue only to
   the next separately researched freeze/product gate.

## Failure policy

If Codex Power fails before edits solely due authentication, quota, or rate
limit, retry the entire product leaf with Grok as the only permitted fallback.
Do not switch agents after edits. Any contract discrepancy, source conflict,
missing tests, or attempt to green live/UI/bulk rows is a fail-closed blocker,
not a reason to merge or claim progress.

## Post-Mortem

- Completed: the root committed the research69 handoff, accepted research-review record, and isolated the authorized organizations slice in one Codex Power leaf with explicit file ownership.
- Deviation: launch configuration initially omitted the model required to price the child's cost cap. This failed before edits or spend; after verification against the local pricing configuration, the child was given `gpt-5.6-terra` and restarted without changing agents.
- Review: research69 independently reconfirmed the unchanged docs body and POST/PUT 401 plus DELETE 405 gate. Its only documentation-hygiene finding was confirmed and corrected in the product-ready research review.
- Verification and cleanup: the root's non-live lint and test suite passed before launch; the full suite remains correctly incomplete because live/UI/vision and bulk evidence are absent. No sensitive material was added to the repository.
- Unresolved coverage slice: await the active product leaf, then perform a separate Grok implementation review before any organizations coverage row can be accepted as offline green.
