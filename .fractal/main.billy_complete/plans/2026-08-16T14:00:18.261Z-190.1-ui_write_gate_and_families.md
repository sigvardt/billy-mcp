## Design choices

1. **TDD first.** The first product edit is a failing test. Run it. Capture the
   16-row failure. Then honesty. Then protocol. Then children.
2. **Gate set is the 16 parity rows.** Discovery create rows stay form-open
   workflows. 99 other parity writes stay `not_applicable` unless a child finds
   a false NA with new dual evidence.
3. **Root owns shared files.** Children never edit `generate_coverage_report.py`,
   `scripts/check_coverage.py`, `src/billy_mcp/server.py`, or
   `src/billy_mcp/browser.py`.
4. **New package `src/billy_mcp/ui_writes/`.** Root lands protocol + empty
   `register_*` stubs. Each child fills one family module. Root already wires
   the stubs in `server.py` before spawn, so children do not touch the shell.
5. **Reuse `ConfirmationStore`.** Preview writes nothing. Execute accepts only
   `confirmation_ticket`. No HTTP `POST /v2/*` on the UI lane.
6. **Live tests serialize.** All children may write offline ticket tests in
   parallel. Only one family runs live submit against the test org at a time.
   Contacts create is first.
7. **Grok only.** Every child: `--agent=grok`. No `codex-power`.

            ui_products_writes ui_ledger_writes ui_files_writes \
            ui_org_writes; do
  child_worktree="$(fractal node init "$name" --path="$PROJECT_DIR" \
      --agent=grok \

      --max-iters=8 --step-timeout=45m \
      --max-depth=0 --max-children=0 --max-descendants=0 \
      | sed -n 's/^Initialized //p')"
  echo "$name $child_worktree"
