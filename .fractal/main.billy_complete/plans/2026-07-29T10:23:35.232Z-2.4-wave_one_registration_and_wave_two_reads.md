record only their real offline implementation and contract evidence in the
generated inventory, and establish a committed contract baseline for the next
three documented filtered-read areas. Preserve the fail-closed qualification
gate: no live row, UI row, write, bulk operation, or completeness claim changes
in this slice.

## Delegation decision

Root keeps Wave 1 server wiring, manifest generation, and coverage evidence:
those files form one coupled integration boundary and the frozen Wave 1
contract reserves their status transitions for root. Splitting them would add
merge friction without independent depth.

After the integration baseline is committed, the three Wave 2 areas are
independent, contractually complete, and file-disjoint. Spawn these focused
Codex Power leaves from `main.billy_complete` with explicit
`--agent=codex-power`, inherited scripts/skills/config, and child limits of
zero. Their NODE contracts must cite the Grok brief and the new wiki page,
forbid server/coverage/wiki/shared-model edits, and require focused fixture
tests without credentials:

```text
wave2_invoice_reads
  owns src/billy_mcp/api/invoice_reads.py
  and tests/api/test_invoice_reads.py
  implements api_invoices_get and api_invoices_list only

wave2_bill_reads
  owns src/billy_mcp/api/bill_reads.py
  and tests/api/test_bill_reads.py
  implements api_bills_get and api_bills_list only

wave2_daybook_transaction_reads
  owns src/billy_mcp/api/daybook_transaction_reads.py
  and tests/api/test_daybook_transaction_reads.py
  implements api_daybook_transactions_get and api_daybook_transactions_list only
```

Create the leaves sequentially only after the root baseline commit, then author
and commit each node contract before its separate `start` command:

```bash
fractal node init wave2_invoice_reads \
  --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
  --base=main.billy_complete --scope=src/billy_mcp/api,tests/api \
  --inherit=scripts --inherit=skills --inherit=config \
  --agent=codex-power --max-depth=0 --max-children=0 --max-descendants=0

fractal node init wave2_bill_reads \
  --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
  --base=main.billy_complete --scope=src/billy_mcp/api,tests/api \
  --inherit=scripts --inherit=skills --inherit=config \
  --agent=codex-power --max-depth=0 --max-children=0 --max-descendants=0

fractal node init wave2_daybook_transaction_reads \
  --path=/Volumes/ssd_1/Repositories/billy-mcp/.worktrees/main.billy_complete \
  --base=main.billy_complete --scope=src/billy_mcp/api,tests/api \
  --inherit=scripts --inherit=skills --inherit=config \
  --agent=codex-power --max-depth=0 --max-children=0 --max-descendants=0
```

Each worker must use the locked client, Pydantic input/success models and typed
errors; allow only its resource's documented filters, global
`page`/`pageSize`/`include`, and documented sort enums; map singular/plural
roots and optional paging; reject unknown filter input locally; and leave every
coverage row untouched. No worker may add writes, specials, bulk operations,
offset paging, browser work, or a live claim.

## Acceptance criteria

- The server registers only real typed coverage and merged read tools; every
  registered `api_*` name has a manifest row and zero stubs are callable.
- Exactly 16 Wave 1 rows, then only the six verified Wave 2 rows after their
  merges, have offline implementation and contract evidence. No `live_tested`
  or UI status flips occur.
- Generated `coverage/status.json` and `coverage/report.md` stay deterministic
  and `complete: false`; the checker rejects any accidental false-green or
  ambiguous-bulk change.
- No credential, raw browser evidence, production-data request, or unbounded
  network/browser capability is introduced.
