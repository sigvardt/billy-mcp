# 2.28 Wave-5f tax write contract freeze

## Objective

Promote the cited, current Grok research into a reviewed, fail-closed Wave-5f
contract for the six singular tax-rate write operations.  The contract is the
only product deliverable in this iteration until an independent Grok reviewer
accepts it.  No tax write tool, coverage green state, live qualification, UI
workflow, bulk tool, webhook, or special route is authorised by this plan.

## Evidence and fixed boundaries

- `.fractal/main.billy_complete/tmp/grok-research.md` is the required cited
  research input.  Its official docs re-fetch is unchanged at ETag
  `hsisik4g9p3603`, MD5 `c2efda0ee4cf9cf200e14910c5fc6996`, and 147934 bytes.
- The API client remains locked to `https://api.billysbilling.com/v2`; product
  modules use only relative `/taxRates` and `/taxRateDeductionComponents`
  paths.
- The shared root `ConfirmationStore` and `WriteProtocolService` remain the
  only write protocol.  Every future execute handler must pass its exact,
  server-owned executor name; no write retries or caller-supplied approval are
  permitted.
- Candidate parent resource: `taxRate` / `taxRates`, with optional response
  root `taxRateDeductionComponents`.  Candidate child resource:
  `taxRateDeductionComponent` / `taxRateDeductionComponents`, with no inferred
  parent response root.
- Candidate operations are singular POST, PUT, and bodyless DELETE for each
  resource.  The 92 bulk rows remain empty-tool red, and unauthenticated DELETE
  200 responses are never live or cleanup evidence.

## Delegation decision

The contract freeze is a small root-owned shared-wiki change, so root writes
and validates it directly.  A clean-context, independent Grok child is required
for the freeze gate because it must re-check current official documentation and
the exact frozen bytes independently.  Do not spawn Codex Power implementation
children before that gate: contract-dependent code would violate the required
research-and-review sequence.  After ACCEPT, a later iteration can split
`src/billy_mcp/api/tax_writes.py` plus its focused tests from root-owned server,
coverage-generator, and cross-executor integration work.

1. Preserve the existing uncommitted Wave-5f research handoff in
   `.fractal/main.billy_complete/memory/state.md`, then create
   `wiki/wave_fivef_ticketed_writes_contract.md`.  Mirror the established
   Wave-5e contract format, explicitly recording all six routes, methods,
   roots, optional parent response mapping, documented field constraints,
   sensitivity, probe limits, and non-goals.
2. Run `wiki update --path=wiki`, `wiki lint --path=wiki`, and
   `wiki lint --path=.fractal/main.billy_complete/memory`.  Review generated
   index changes and ensure neither shared nor private durable text contains
   credentials, raw probe payloads, screenshots, HARs, or an accidental green
   qualification claim.
3. Run the narrow non-live regression baseline for the protocol and closest
   clone: `tests/unit/test_write_protocol.py`, `tests/unit/test_confirmations.py`,
   `tests/api/test_catalog_writes.py`, `tests/api/test_tax_reads.py`, and
   `tests/coverage/test_coverage_inventory.py`.  Also run formatter, Ruff, and
   Pyright over the touched surfaces before committing the freeze.
4. Commit the freeze and research-state handoff on root.  Only after that clean
   commit, initialise and start `wave5f_freeze_review` with explicit
   `--agent=grok`.  Give it sole ownership of
   `wiki/wave_fivef_freeze_independent_review.md`; require a cited ACCEPT or

   fail-closed coverage.  It must make no code or coverage-status edits.
5. While the reviewer runs, do not implement tax writes.  On a cited ACCEPT,
   merge only the review page, lint the project wiki, and record the
   authoritative offline-only decision in root memory.  On REJECT, make only
   the cited contract correction and obtain a new Grok review.
