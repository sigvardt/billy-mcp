## Delegation decision

The only immediately runnable work was the fallback candidate, and its child
is now complete. The remaining work is strictly sequential: an independent
contract verdict must precede implementation, and an independent product verdict
must follow implementation. Spawning implementation now would fork before its
contract gate and create avoidable rework, so this plan queues three focused
children at their respective gates.

## Execution plan

1. In the next integration action, inspect the candidate's project deliverables
   and the child-seed metadata, confirm that it adds no product code or coverage
   promotion, then merge it with:

   ```sh
   git merge --no-ff -m "merge main.billy_complete.wave5h_freeze_contract_codex_fallback" \
     main.billy_complete.wave5h_freeze_contract_codex_fallback
   ```

   Run `wiki lint --path=wiki`; retain the candidate's fallback status in prose.
   The standard merge retains the child seed for audit consistency with prior
   child merges; do not copy any scratch evidence or treat child memory/plans as
   a root implementation deliverable.

2. After that merge is committed, configure and start a **Grok** leaf named
   `wave5h_freeze_review` with `--agent=grok`. It owns only a new durable
   `wiki/wave_fiveh_freeze_independent_review.md` record and its generated index

   issue an explicit ACCEPT or REJECT, cite the docs fingerprint, and leave

   rate-limit failure before edits is retried once with `--agent=codex-power`
   as a clearly non-authoritative supplemental audit; that fallback cannot
   satisfy the Grok acceptance gate.

3. Only if the Grok freeze review is ACCEPT, configure and start a
   **Codex Power** leaf named `wave5h_attachment_product` with
   `--agent=codex-power`. Its exclusive project ownership is:

   - `src/billy_mcp/api/attachment_writes.py`

   - `tests/api/test_attachment_writes.py`
   - `tests/unit/test_coverage_server.py`

     `coverage/report.md`

   It must clone the tested ticketed-write pattern using opaque inner
   `attachment` payloads, `additional_plural_roots=()`, the root's shared
   confirmation store/service, and exactly the six names cited by research35.
   It must test strict schemas, paths, bodyless delete, optional delete metadata,

   create, UI, or live claims.

4. After the product is merged and its local checks pass, configure and start a
   separate **Grok** leaf named `wave5h_product_review` with `--agent=grok`.
   It owns only `wiki/wave_fiveh_product_independent_review.md` and its index
   row. It must independently verify routes, tool schemas, ticket binding,
   tests, registry 208, coverage 151, red live/UI/bulk/special rows, and issue

   only and cannot replace this verdict.

5. A REJECT at either review stops the downstream child. Preserve all affected
   rows red, record the finding, and route a bounded repair through Codex Power
