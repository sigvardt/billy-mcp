# 2.27 Wave-5e root integration and independent product review

## Objective

Integrate the completed, offline-only Wave-5e bill and bill-line ticketed-write
modules under the accepted `fc8118e` contract; prove the root registration,
cross-executor boundary, coverage evidence, and non-live suite; then launch a
fresh independent Grok product review from the exact committed root baseline.
Keep live, UI, vision, bulk, special-route, and completeness rows fail-closed.

  official documentation at ETag `hsisik4g9p3603` and MD5
  `c2efda0ee4cf9cf200e14910c5fc6996`; Wave-5e needs no further contract
  research before integration.
- The two product leaves contain only two acceptable project artifacts each:
  `bill_writes.py` / `test_bill_writes.py`, and `bill_line_writes.py` /

  no-fast-forward merge commits.
- The accepted six-row contract fixes `/bills` + `bill` + `bills` with no
  additional root, and `/billLines` + `billLine` + `billLines` with optional
  `bills`. Both registrars must share the root `ConfirmationStore` and
  `WriteProtocolService` and preserve exact executor-name ticket binding.
- The uncommitted memory update is an interrupted research handoff for the

  begin Wave-5f implementation before this product gate closes.

## Delegation decision

The completed leaf modules are not re-delegated: they need one root-owned
registration and coverage integration. The post-integration product audit is
independent, current-contract work with a clean baseline, so root will spawn
one focused `--agent=grok` review child only after the integration commit is
available. That child owns `wiki/wave_fivee_product_independent_review.md`
only and must issue a documented PASS/REJECT verdict without making a
completeness or live/UI claim.

## Execution sequence

1. Inspect each completed child from `git archive` and its focused test
   contract. Merge each branch with `--no-ff --no-commit`, restore the child
   seed directory to the pre-merge root state, stage only its two owned project
   files, and commit the labelled merge. Do not import node configuration,
   plans, skills, or generated assets.
2. Register both write modules in `server.py` with the existing shared client
   and `WriteProtocolService`. Add root-owned
   `tests/api/test_bill_cross_executor.py`, patterned after the invoice pair,
   to prove both wrong-executor directions fail before ticket consumption and
   the correct executor performs the single expected request.
3. Add the exact six offline evidence tuples in
   `scripts/generate_coverage_report.py`; extend registry assertions and any
   coverage-server test fixtures for the 178 `api_*` tools / 136 implemented
   and contract-tested API rows. Regenerate checked-in coverage artifacts and
   assert live/vision remain zero and `complete` remains false.
4. Run formatting, Ruff, Pyright, both leaf suites, the cross-executor and
   coverage suites, coverage generation, repository policy/safety checks, and
   the complete non-live test suite. Correct only defects revealed by these
   checks; no live or browser test is authorized without the dedicated
   non-production credentials.
5. Commit the root integration plus the preserved research-state handoff, then
   configure and start `wave5e_product_review` with `--agent=grok`, frozen to
   that commit. Its `NODE.md` must restrict ownership to the review wiki page,
   require inspection of the six exact routes/roots, optional bill-parent
   mapping, ticket replay/executor binding, registry/evidence arithmetic, and
   fail-closed coverage, and prohibit replacing the mandatory product audit
   with a fallback result.
6. Monitor the reviewer. On a documented ACCEPT, merge only the review page,
   lint the project wiki, record the authoritative offline decision, and leave
   all unqualified rows red. On REJECT, implement only the cited correction and
   obtain a new Grok review.
