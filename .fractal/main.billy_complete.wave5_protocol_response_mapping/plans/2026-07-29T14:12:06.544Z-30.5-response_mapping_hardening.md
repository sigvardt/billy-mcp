# 30.5 Response mapping hardening

## Goal

Implement the frozen Wave-5a response-mapping hardening in the shared write
protocol. The cited source fingerprint is ETag `hsisik4g9p3603`, MD5
`c2efda0ee4cf9cf200e14910c5fc6996`.

## Scope and decision

This node is childless (`max_depth`, `max_children`, and `max_descendants` are
all zero), so the two tightly coupled files remain one atomic local change. No
fresh research, registration, coverage, client, confirmation, auth, UI/browser,
inventory, bulk, or shared-wiki work is permitted.

## Implementation

1. Extend `WriteOperationSpec` with an immutable declaration for additional
   documented changed plural roots, retaining `plural_root` as the primary root.
   Carry the declared root set into `_PreparedWrite` so execution is bound to
   the server-known preview specification.
2. Update response mapping to keep the primary root's existing required
   non-delete behaviour, then include every valid, present declared additional
   root. Ignore undeclared roots and omit declared roots absent from the
   response. Keep delete and primary-root `meta.deletedRecords` handling
   unchanged, including typed validation errors for malformed mapped data.
3. Add MockTransport fixtures for a products-plus-productPrices response and a
   response missing a declared optional root. Retain the existing single-root,
   delete, upstream-error, ticket, escaped-path, canonical-binding, and
   no-retry tests.

and the node non-live test script. Inspect the scoped diff and status, commit
only the two product files plus this node's plan/memory bookkeeping, report the
commit and checks through the outbox, then finish the node. Parent integration
and independent review are explicitly out of scope.
