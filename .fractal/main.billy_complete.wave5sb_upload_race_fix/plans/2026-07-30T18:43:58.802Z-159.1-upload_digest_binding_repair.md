# 159.1 Upload digest binding repair

## Scope and decision

This leaf node has no child capacity, so the narrowly coupled production/test repair remains local. The sole production change is in `src/billy_mcp/api/file_upload_writes.py`; the sole test change is in `tests/api/test_file_upload_writes.py`.

The existing post-preview identity comparison remains responsible for canonical-path containment, symlink-escape rejection, regular-file validation, and size/mtime/digest revalidation. Add one comparison after the final `read_bytes()` call: SHA-256 of that transient in-memory buffer must equal the ticket's prepared digest before `BillyHttpClient.post_file` is called. On mismatch, return `FILE_CHANGED` and do not call the client. Do not retain or log the buffer.

## Execution

1. Add the in-memory byte-buffer digest guard directly between the successful read and `post_file`, preserving the existing read-error result and all ticket lifecycle behavior.
2. Add a deterministic focused test that monkeypatches `Path.read_bytes` to replace the target after identity validation but before it returns the transport buffer; assert `FILE_CHANGED` and an empty recorded request list.
3. Keep the existing successful raw-binary request test as the matching-digest proof, including exact request-body and header assertions.

## Committed-authority review

Design §§8.3–8.4 requires the ticket-bound canonical path and SHA-256 identity
to be revalidated at execute time, with changed files and symlink escapes
rejected. The product-ready handoff additionally fixes the raw-byte body,
ticket-only execution, one-use semantics, no-retry policy, and redaction
boundary.

The implemented guard is immediately after the successful `read_bytes()`
result and immediately before `post_file`. It hashes only the transient
in-memory buffer, compares it to the previewed identity digest, and returns
`FILE_CHANGED` before transport on mismatch. The focused patched-read test
replaces the file after identity revalidation and proves that this path records
no HTTP request. The existing raw-upload test proves matching bytes are sent
unchanged, while the surrounding focused tests retain ticket, containment,
symlink, no-retry, and redaction protections. No coverage or API contract
surface is changed.
