# 176.1 Offline auth credential references and pre-submit login

## Contract and scope

Implement only the research92 offline credential-reference and pre-submit login
transition.  The authoritative sources are
`wiki/auth_credentials_pre_submit_research.md`, the parent worktree's
research92 scratch brief, and the approved design.  Do not perform browser or
API network activity, resolve actual Billy material, change coverage state, add
API/UI tools, or infer a post-login or organisation state.

This is a leaf (`max_depth=0`, `max_children=0`, `max_descendants=0`), so the
work remains local rather than delegated.

## Implementation

1. Add strict serialisable opaque-reference types and an injectable resolver in
   `src/billy_mcp/credentials.py`.  Configuration retains only two required
   opaque references sourced from configuration environment names; the resolver
   exposes values only as local ephemeral inputs to the fixed browser
   transition.  No unobserved challenge reference is configured, resolved, or
   located. Missing, blank, or resolver-failing required references collapse to
   the redacted `AUTH_REQUIRED` result.
2. Extend `AppConfig` with the safe browser-reference settings while leaving
   the existing API credential resolver untouched.  No model, configuration
   dump, tool schema, exception, or result will expose a credential value or a
   meaningful account identity.
3. Add strict empty Pydantic inputs and stable auth result models.  Register
   only purpose-built `auth_login_start` and `auth_login_wait` operations,
   using the established injectable auth-service pattern rather than accepting
   navigation, DOM, selector, click, or credential parameters.
4. Extend `BrowserRuntime` through internal-only page seams: start its existing
   headless/download-disabled/egress-guarded persistent context; navigate only
   to `https://mit.billy.dk/`; require the exact `/login` URL and the observed
   one-visible-control signature; resolve only after the first validation; and
   repeat URL/signature validation immediately before each internal fill/click.
   Keep remember-me unchecked, never resolve the optional challenge reference,
   and close the page in `finally` for all outcomes.  Drift before resolution
   is `UI_CHANGED`; egress setup failure is `EGRESS_DENIED`; all unexpected
   failures are redacted `BILLY_ERROR`.
5. Add focused fakes-only tests for opaque schemas/configuration, resolver
   errors and missing inputs, exact signature counts/visibility/labels,
   validation-before-resolution and revalidation ordering, headless/download
   and egress invariants, page closure, and secret redaction.  Update the
   existing server registration assertions for precisely the new typed auth
   tools without altering coverage fixtures or manifests.

Run formatter, Ruff, Pyright, focused auth/config/browser/server tests,

## Post-Mortem

Implemented opaque reference configuration and a keyring-backed injectable
resolver, plus the two fixed, empty-input auth tools. The browser seam now
revalidates the frozen URL/control signature before resolution and every
internal action; it leaves the future challenge path entirely absent. Tests use
only fakes and prove fail-closed results, ordering, closure, redaction, and
schema boundaries.

The original plan was narrowed by removing even a reserved future challenge
locator: the frozen boundary requires that unobserved challenges are not
located, not merely left unresolved. Live login, organisation UI, bootstrap,
coverage qualification, and independent Grok product review remain outside
this delivered offline slice.
