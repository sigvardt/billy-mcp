## Design

### Tools

| Tool | Input | Behaviour |
| --- | --- | --- |
| `ui_organizations_update_preview` | strict Pydantic, `extra=forbid`; allowlisted reversible company fields only | Validate, fail closed, `protocol.preview(...)`. No browser. No HTTP. |
| `ui_organizations_update_execute` | `UiWriteExecuteInput`: only `confirmation_ticket` | `protocol.consume(...)` then optional submitter. No business payload. |

Preview binds `execute_tool_name="ui_organizations_update_execute"`, target
`settings_company`, expected effect
`{action: update, resource: organization, surface: settings_company}`.

### Allowlist and fail-closed

Allowlist (company / Virksomhed panel only): `phone` (live mutation field),
plus the same field for restore. Do not mutate `name` or `registrationNo`.

Reject at preview (`VALIDATION_ERROR`) if the request names or implies:

- users / Brugere
- access tokens / Adgangsnøgler
- subscription / Abonnement
- VAT / Moms / filings
- payments
- owners / `Tilføj ejer`
- any field outside the allowlist

### Submitter

`register_ui_organization_write_tools(server, protocol, *, submitter=None)`
keeps the root call site valid.

- Missing submitter: return `ToolError` **without** consuming the ticket.
- Unit tests inject a recording submitter. It records the bound request and
  never opens a browser or talks to `api.billysbilling.com`.
- Live tests inject a browser submitter that edits Telefon on
  `/:org_slug/settings`, clicks `Gem ændringer`, then restores the original
  value. Never `BrowserRuntime` as the pass proof: assertions go through
  `server.call_tool`.

### Qualification

All pass/fail proof is FastMCP `call_tool` on an isolated server that only
registers this family (plus the shared protocol). Do not use `create_server`
as the unit-test harness (it pulls the whole tool set).
