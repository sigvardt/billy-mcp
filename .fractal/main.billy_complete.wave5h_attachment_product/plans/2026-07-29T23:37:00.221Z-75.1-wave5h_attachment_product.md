# 75.1 Wave-5h Attachment Product

## Scope and decision

Implement the accepted offline attachment JSON CUD slice locally. This node is
a leaf (`max_depth`, `max_children`, and `max_descendants` are all zero), so
the work cannot be delegated. The cited Wave-5h freeze and product-ready review
authorise exactly three documented rows and six tools; no live, binary-file,
bulk, UI, vision, auth, or Wave-5i work is in scope.

## Delivery plan

1. Inspect the completed singular-write module and its contract/cross-executor
   tests, plus the root registration and generated-coverage evidence contract.
2. Add `attachment_writes.py` with strict flat preview models around opaque
   `attachment` JSON and exactly the create, partial-update, and bodyless-delete
   preview/execute pairs. Bind each operation to its precise server-owned
   execute name through the root service; map only the frozen `attachments`
   roots.
3. Register the new module through the existing root `WriteProtocolService`.
   Extend the root registry expectation to 208 API tools and add focused tests
   for schemas, opaque preservation, wire shapes, response boundaries, typed
   errors, and ticket safety. Include a cross-resource executor-name mismatch
   proof that fails before ticket use or HTTP.
4. Run focused attachment tests first. When they pass, add only the three
   attachment CUD evidence-map rows, regenerate the coverage artifacts, and
   assert 151 implemented/contract-tested API rows while live/UI/vision/bulk
   stay fail-closed and `complete` stays false.
5. Run formatting, lint/type checks, coverage/policy checks, and the complete
   non-live test script. Record durable implementation facts in node memory,
   commit through `fractal commit`, report the commit and verification totals to
   the parent by radio, and finish only after the worktree is clean.

## Risks and checks

- Preserve opaque inner attachment fields; do not infer owner or file
  serialization from the unrelated binary `/files` endpoint.
- Ensure update rejects a mismatching optional `attachment.id` before preview
  issuance, and delete binds canonical `{"id": id}` with no HTTP body.
- Keep executor-name binding exact: mismatches must be rejected before
  confirmation-ticket consumption and before an HTTP request.
- Do not edit shared `write_protocol.py`, other write modules, manifest-source
  parsing, browser/auth runtime, or project scripts. Escalate a concrete
  blocker if any would be required.
