# 165.5 Wave-5t live residual/bulk gate harness

Scope is strictly the four owned files. The frozen Research88 brief at
`.fractal/main.billy_complete.wave5t_live_gate_harness/tmp/grok-research.md`
is the contract source; the official docs fingerprint remains unchanged. This
leaf cannot spawn children, so no delegation is possible.

1. Add `src/billy_mcp/live_probe.py` as a strict Pydantic safety boundary.
   Keep the API base as a literal, retain token material only in a local
   execution scope, and model non-sensitive configurations, results,
   candidates, evidence summaries, and blocked reasons. Construct exactly 29
   residual operations and 92 bulk candidates from static Research88 tuples;
   reject an invalid absolute/relative base before any client is created.

2. Make the runner fail closed in a deliberate order: a missing token returns
   the serialisable `skipped_no_token` success result with no client, network,
   or evidence directory; a present token then requires equal explicit
   `BILLY_TEST_ORGANIZATION_ID` and `BILLY_LIVE_PROBE_ORGANIZATION_GUARD`
   values before any request. Do not derive or send an organisation context
   from undocumented headers. A configuration failure is non-success and has
   no network or evidence side effect.

3. Limit authenticated observation to static `OPTIONS` requests against the
   candidate matrix only, with no request body and no mutable method. Treat all
   returned statuses (including 401, 200 meta responses, and Supports-like
   information) as non-contract evidence. Do not create persistent data or
   residual/bulk tools. Keep a typed, inert cleanup ledger that refuses to
   accept an unproven persistent resource; any future write path must require a
   unique test tag, reverse-order cleanup, independent read-back, and a visible
   cleanup failure rather than silently continuing.

4. Create external evidence only after the authenticated guard and first
   observation. Require an absolute out-of-repository path, create/check mode
   `0700` and the current owner, and serialise only redacted candidate IDs,
   routes, methods, status classifications, and cleanup state. Never retain a
   token, body, headers, customer data, screenshot, HAR, trace, or raw response.

5. Create `scripts/run_live_probe.py` as a narrow JSON CLI. It must internally
   invoke the runner, print only the safe typed result, return zero for the
   no-token skip, and not expose arbitrary base URLs, routes, shell execution,
   or a generic HTTP interface.

6. Add deterministic unit tests for missing token/no network/no evidence,
   missing and mismatched organisation guards, base locking, exact 121-candidate
   construction, token/result redaction, evidence owner-only permissions, and
   refusal to use inferred meta/401/Supports output as a contract. Add a
   `pytest.mark.live` test that skips without credentials, targets only the
   guarded non-production configuration, and uses a mock-free real runner only
   when explicitly configured.

7. Run focused tests, exercise the CLI with `BILLY_API_TOKEN` absent while
   asserting no repository evidence artifact, then run node tests, lint, the
   repository policy check, coverage non-mutation checks, and a restricted diff
   audit before commit. No coverage or shared-wiki file is changed.
