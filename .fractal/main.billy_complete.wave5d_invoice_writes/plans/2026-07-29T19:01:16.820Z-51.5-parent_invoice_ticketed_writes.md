possible. Implement only the parent-invoice half of the cited Wave-5d freeze in
`src/billy_mcp/api/invoice_writes.py` and
`tests/api/test_invoice_writes.py`. The root-owned server wiring and coverage
inventory remain outside this leaf.

## Implementation

1. Add the invoice write module with strict outer Pydantic preview models and
   opaque `invoice` dictionaries. Register exactly the create, update, and
   delete preview/execute pairs through the root-owned `WriteProtocolService`.
2. Build the three operation specifications with the exact client-relative
   collection path `/invoices`, singular root `invoice`, plural root `invoices`,
   server-owned execute names, and expected-effect state. Keep DELETE payloads
   absent, and reject an update body `invoice.id` if it disagrees with the route
   `id` while allowing absent and otherwise unknown inner fields.
3. Reproduce the accepted Wave-5c local-test shape for invoice tools: flat
   schema registration, strict outer inputs, non-mutating previews, exact
   request method/path/root body, bodyless deletes, ticket tamper/expiry/replay
   and binding protections, same-module executor mismatch before HTTP, typed
   auth/not-found propagation, optional delete metadata, and an explicit
   one-request failure case proving no write retry.
