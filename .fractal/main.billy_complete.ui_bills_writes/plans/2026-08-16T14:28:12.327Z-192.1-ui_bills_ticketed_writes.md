## Design

Mirror API ticketed writes (`src/billy_mcp/api/bill_writes.py` and
`tests/api/test_contact_balance_payment_writes.py`) on the UI protocol, not
the HTTP write protocol.

### Register signature

Keep the two positional args root already passes. Add an optional submitter
so tests can inject a recorder without editing `server.py`:

```python
def register_ui_bill_write_tools(
    server: FastMCP,
    protocol: UiWriteProtocol,
    submitter: BillUiSubmitter | None = None,
) -> None:
```

Default submitter is fail-closed: after a valid consume it returns
`ToolError(VALIDATION_ERROR)` with message that live submit waits for root
radio go-ahead. It never opens a browser and never calls the Billy HTTP API.

### Preview

Pydantic, `extra="forbid"`, flat fields (no nested `input`). Force draft-only.

| Tool | Fields |
| --- | --- |
| `ui_bills_create_preview` | `unique_tag` (minLength 1) |
| `ui_bills_update_preview` | `id` (minLength 1), `unique_tag` (minLength 1) |
| `ui_bills_delete_preview` | `id` (minLength 1), `unique_tag` (minLength 1) |

Reject any payment, approve, email, or send field by not declaring them
(`extra="forbid"`). Bind `expected_effect_state` with
`{"action": "...", "resource": "bill", "draft_only": true}`. Canonical request
includes `unique_tag` and `draft_only: true`. Preview calls
`protocol.preview` only. Submitter is not invoked.

### Execute

Accept only `confirmation_ticket` (`UiWriteExecuteInput`). Call
`protocol.consume(..., execute_tool_name=...)`. On `ToolError`, return it
(replay, expiry, mismatch, invalid). On success, call the submitter with the
prepared binding. Return a small result model defined in `bills.py`
(`submitted`, `action`, `unique_tag`). Do not reuse `WriteExecutionResult`
(that type is HTTP record mapping).

### Submitter

Protocol, in `bills.py`:

- `RecordingBillUiSubmitter` for offline tests: appends the prepared action,
  returns `submitted=True`. No network.
- Default `LiveSlotBlockedSubmitter`: no browser, no HTTP, `VALIDATION_ERROR`.
- Later real UI driver (after go-ahead): draft create via `Gem som kladde`,
  tagged update, delete or restore. Never pay. Not built until root radios.

## Offline tests (must cover)

All through FastMCP `call_tool`, never `BrowserRuntime`.

- Registers exactly the six named tools. Schemas are flat, `additionalProperties`
  false, execute properties `{"confirmation_ticket"}` with `minLength: 1`.
- Preview returns ticket + summary + canonical request. Submit recorder stays
  empty (preview no-submit).
- Execute once: recorder has one matching action. Result `submitted` is true.
- Replay: `CONFIRMATION_CONSUMED`. Recorder still length 1.
- Expiry: advance clock past `MAX_TICKET_TTL`. `CONFIRMATION_EXPIRED`.
  Recorder empty for that ticket.
- Wrong-tool: create ticket into update execute. `CONFIRMATION_MISMATCH`.
  Recorder empty.
- Tampered ticket: `CONFIRMATION_INVALID`.
- Default (no injected submitter) execute after preview: `VALIDATION_ERROR`
  and no HTTP.
- No request is sent to `api.billysbilling.com` (do not construct a Billy
  HTTP client in these tests).
- Extra preview fields and empty `unique_tag`/`id` raise `ValidationError`.

Reuse the `Clock` + `ConfirmationStore(clock)` pattern from
`tests/unit/test_ui_write_protocol.py` and the `call_tool` helper from
`tests/api/test_contact_balance_payment_writes.py`.
