# 1.1 Bootstrap authenticated API reads

Deliver the first read-only API module in the two assigned product files. This
node is a leaf (`max_depth`, `max_children`, and `max_descendants` are all
zero), so there is no separable child delegation to perform.

1. Add `src/billy_mcp/api/bootstrap_reads.py` with real Pydantic input and
   success models plus a registration function for only `api_user_get`,
   `api_user_list_organizations`, `api_organizations_get`, and
   `api_organizations_list`. Inject `BillyHttpClient`, use only the documented
   relative GET paths, preserve just the documented roots, and pass through
   `ToolError` unchanged. Use opaque typed mappings for undocumented record
   fields and map optional `meta.paging` without inventing a payload schema.
2. Restrict public inputs to the frozen contract: the organisation get ID and
   optional include; the organisation list page, pageSize, include,
   sortProperty, and ASC/DESC sortDirection; no filters, offsets, generic HTTP,
   writes, or server wiring. Confirm the FastMCP registration schema presents
   precisely those inputs.
3. Add `tests/api/test_bootstrap_reads.py` with mock-transport fixtures that
   assert paths, query construction, four root mappings, absent/present paging
   boundaries, registration names/schema, and documented 401 envelopes mapping
   to typed `AUTH_REQUIRED` errors. Keep `live_tested` false: do not use a live
   token or make a network request.
4. Run ruff format/check, Pyright, focused pytest, and the seeded lint/test
   scripts. If any required shared interface is unavailable, stop rather than
   edit it and report the verified need to the parent via radio.
5. Commit only the two product files, report coverage IDs
   `api.special.user_get`, `api.special.user_organizations`,
   `api.organizations.get`, and `api.organizations.list` with the focused test
   reference, then finish after the required handoff and state cleanup.

## Post-Mortem

### Accomplishments

- Added the four typed, read-only bootstrap tool registrations with injected
  `BillyHttpClient`, documented paths and query controls, opaque root mapping,
  optional paging, and recursive sensitive-value redaction.
- Added six mock-transport contract tests covering registration schema, request
  construction, singular/list response roots, paging boundaries, and both
  documented authentication envelopes.

  `result` wrapper. The registration test asserts both variants in that schema.
- No shared server, coverage, configuration, or live-credential changes were
  needed or made.
