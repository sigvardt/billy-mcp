# 1.1 Wave 4 Bank Reads

## Objective

Implement and contract-test exactly ten offline, read-only bank/balance tools in
`src/billy_mcp/api/bank_reads.py` and `tests/api/test_bank_reads.py`.

## Constraints

- This is a leaf (`max_depth`, `max_children`, and `max_descendants` are zero),
  so no delegation is possible or planned.
- The cited Grok brief and the Wave-4 wiki contract are authoritative. Use only
  the locked client and relative collection paths.
- Keep successful records opaque and preserve optional `meta.paging`; do not
  add bank fields, filters, enum sets, write behavior, server registration,
  coverage updates, redaction changes, live claims, or browser artifacts.

## Work

1. Mirror the Wave-3 file/attachment typed-read structure with strict shared
   get/list request models, opaque payload/meta models, URL-encoded IDs,
   response-root validation, and reusable request/response helpers.
2. Add service handlers and module-local FastMCP registration for exactly:
   `bankPayments`, `bankLineMatches`, `bankLines`,
   `bankLineSubjectAssociations`, and `balanceModifiers`, each with get/list
   paths and the frozen singular/plural roots.
3. Create synthetic contract tests covering every handler route/root, get ID
   encoding, list query serialization, present and absent `meta.paging`,
   forbidden unknown/offset/parent inputs, both typed Billy 401 mappings, and
   the exact ten locally registered schemas.
4. Run formatting, Ruff, Pyright, and the focused test module. Address only
   failures in the owned module/tests, then leave parent-owned integration and
   coverage work untouched.

## Acceptance

The two owned files pass the required focused checks, contain no credentials or
non-synthetic bank data, and expose only the ten frozen read tools for the
parent to integrate later.

## Post-Mortem

- Delivered the two owned files with ten frozen bank/balance get/list tools,
  strict flat inputs, encoded identifiers, opaque successful records, optional
  metadata paging, and typed 401 handling.
- Independent Grok review passed with no required finding. Its optional absent
  `meta.paging` serialization polish was implemented with a regression test.
- Ruff format/check, Pyright, 25 focused tests, and the 249-test non-live suite
  pass. Full qualification runs all tests successfully and then correctly fails
  only at the global completeness gate: unresolved inventory, live, UI, and
  ambiguous-bulk rows remain red.
- No live probes, browser artifacts, credentials, coverage changes, root
  registration, redaction changes, write semantics, or non-synthetic bank data
  were introduced. Only the two owned product files are intended for commit.
