## Implementation

1. Add `src/billy_mcp/api/bank_line_writes.py` using the established
   `sales_tax_account_meta_writes.py` shape:

   - Define strict flat Pydantic preview models for create/update/delete of all
     three resources. Use exact camel-case public fields, opaque
     `dict[str, JsonValue]` inner payloads, non-empty route ids, and
     model validators that reject an inner `id` unequal to the route id.
   - Register exactly the eighteen frozen public tool names. Every execute
     handler accepts only a non-empty `confirmation_ticket` and passes its own
     literal, server-owned execute name to `WriteProtocolService.execute`.
   - Build fixed `WriteOperationSpec` values for:
     `/bankLineMatches` / `bankLineMatch` / `bankLineMatches` with
     `("bankLines", "bankLineSubjectAssociations")` as optional returned roots;
     `/bankLines` / `bankLine` / `bankLines` with no additional roots; and
     `/bankLineSubjectAssociations` / `bankLineSubjectAssociation` /
     `bankLineSubjectAssociations` with no additional roots.
   - Use POST for creates, partial PUT with encoded route id for updates, and
     bodyless DELETE for deletes. Expected effect state contains only action,
     singular resource, and id where applicable.

2. Add `tests/api/test_bank_line_writes.py` with real local mock-transport
   contract evidence:

   - Assert all eighteen schemas are flat, strict, and expose only the frozen
     public fields; ids and tickets have `minLength: 1`.
   - Reject outer extras, empty ids, and route/body id mismatches while
     preserving unknown nested JSON and matching ids.
   - Parameterize all nine previews to prove no HTTP, exact canonical requests,
     exact expected effects, and non-empty tickets.
   - Parameterize all nine executions to prove one request, exact method,
     locked `/v2` URL resolution from client-relative paths, escaped ids,
     singular request roots, and empty DELETE bodies.
   - Prove non-delete primary roots are required; match tools map optional
     `bankLines` and `bankLineSubjectAssociations` only when actually returned;
     line and association tools ignore/invent no parent or sibling roots; and
     delete metadata is surfaced only when present for declared roots.
   - Cover tamper, expiry, replay, same-resource wrong executor, mutated
     executor/organisation/target/payload/effect bindings, empty-token typed
     auth errors, upstream typed errors, and one-attempt/no-retry failure.

3. Add `tests/api/test_bank_line_cross_executor.py` against `create_server()`:

   - Monkeypatch only `BillyHttpClient.request` to record attempted writes.
   - Preview through each bank-line family, invoke same-family and cross-family
     wrong executors, and assert `CONFIRMATION_MISMATCH` before consumption and
     before HTTP.
   - Execute each still-valid ticket through its exact executor and assert the
     original canonical request and declared response roots, proving all
     eighteen tools share the root's single write service/store.

4. Wire the module into `src/billy_mcp/server.py`:

   - Import and call `register_bank_line_write_tools` once using the existing
     `client` and `write_protocol`.
   - Extend `tests/unit/test_coverage_server.py` with a disjoint eighteen-name
     Wave-5j set, assert its size, update the exact API registry count from 220
     to 238, and include the set in the full registry equality.

5. Qualify coverage only after the generator ownership issue is resolved:
