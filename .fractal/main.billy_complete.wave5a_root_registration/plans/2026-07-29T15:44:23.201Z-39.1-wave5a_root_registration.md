# 39.1 Wave-5a root registration

## Scope and decision

This delivery coupled server registration and generated evidence for the same
30 preview/execute write tools. The node was a zero-depth leaf, so it completed
the work directly. The frozen Wave-5 contract and accepted catalog/daybook
review were the sufficient offline sources; no live, UI, browser, bulk,
special-route, or credential work changed.

## Work

1. Updated `create_server` to construct exactly one `ConfirmationStore` and
   shared `WriteProtocolService` per server instance, then registered the
   contact, contact-person, catalog, and daybook write families alongside the
   existing reads and coverage tools. The instructions now describe ticketed
   write capability accurately.
2. Extended `tests/unit/test_coverage_server.py` with the 30 accepted preview
   and execute names. The preserved 94 read assertions prove the final surface
   contains 124 `api_*` names plus exactly two coverage names.
3. Added evidence-map entries only for the fifteen frozen CUD inventory ids in
   `scripts/generate_coverage_report.py`; execute twins remain absent from the
   inventory because their preview names are the documented rows.
4. Ran the coverage generator. The resulting status has 109 implemented and
   contract-tested rows, zero live-tested rows, 92 empty-tool bulk rows,
   all-red UI, and `complete: false`.
5. Verified formatting, Ruff, Pyright, the five write suites plus protocol and
   coverage/server tests, coverage and repository-policy scripts, and the
   non-live/non-vision pytest suite. The review found only the owned product
   paths and generated artifacts, with no secret or raw-evidence material.
