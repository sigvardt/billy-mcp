# 161.1 Upload descriptor containment repair

## Scope and approach

This leaf cannot delegate: depth, child, and descendant limits are all zero.
The repair is limited to the owned upload service and its focused tests.

1. Replace execute's path-based read after identity validation with a
   descriptor-relative traversal from each canonical configured upload root.
   Open every directory and the terminal regular file with no-follow semantics,
   obtain metadata from the terminal descriptor, compare it to the preview
   identity, then read and hash the transport buffer from that descriptor.
2. Preserve the existing consume/discard order and error contract.  A changed
   in-root file remains `FILE_CHANGED`; descriptor traversal failures that
   reveal a symlink/non-regular escape return `FILE_NOT_ALLOWED`; neither path
   can call the HTTP client.
3. Replace the obsolete `Path.read_bytes` race regression with deterministic
   descriptor-open hooks.  Cover a terminal same-digest symlink to an
   outside-root file and an intermediate-directory swap to an outside symlink,
   each proving zero transport requests.  Retain the existing binary-body,
   ticket, redaction, header, expiry, replay, and changed-file coverage.
4. Run the focused upload tests, lint, and the node test script.  After the
   source and test changes are committed, repeat the focused test from a clean
   `git archive` checkout and report exact outcomes plus the still-open parent
   Grok audit gate.

## Post-Mortem

### Accomplishments

- Replaced execute's path-based read with no-follow descriptor traversal rooted
  at the configured canonical upload roots.
- Added deterministic terminal and intermediate same-digest symlink-race tests
  that assert `FILE_NOT_ALLOWED` and zero HTTP requests.
- Preserved the changed-byte race as `FILE_CHANGED`, the descriptor-read SHA-256
  check, and the existing ticket, binary-body, redaction, and header coverage.

### Deviations

- Review refined descriptor-open error mapping so vanished or changed permitted
  files preserve `FILE_CHANGED`, while no-follow and non-directory failures are
  `FILE_NOT_ALLOWED`.

### Next-Iteration Notes

- Commit the scoped repair, verify focused tests from a clean archive, and hand
  off the result without representing the parent-required Grok audit as closed.
