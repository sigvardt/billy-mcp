# 1.1 Daybook parent read tools

Implement the frozen, offline-only Daybooks and Daybook Balance Accounts
get/list contract in the two owned files. No child can be spawned because this
node has zero depth, child, and descendant capacity; the tightly coupled module
and its focused contract test therefore remain one leaf task.

1. Add `daybook_reads.py` following the current unfiltered read conventions:
   strict Pydantic request models, opaque allow-extra records, optional
   `meta.paging`, URL-encoded identifiers, and a module-local four-tool
   FastMCP registration function. Keep list query construction to
   `page`, `pageSize`, `include`, free `sortProperty`, and `ASC`/`DESC`
   `sortDirection`.
2. Add focused mock-transport tests for both resources: paths, encoded IDs,
   query values, roots and absent/present paging, invalid/invented filters,
   typed 401 mapping, and the exact registration surface.
3. Run the focused pytest file, Ruff format/check, and Pyright. Inspect the
   resulting diff for scope and verify the committed bytes before handoff.
