# 184.1 UI login surface contract brief

## Objective

Publish only `wiki/ui_login_surface_contract.md`: a durable, cited contract
brief that preserves the supplied Grok evidence without initiating any new UI
or API research.

## Evidence and decision

- Treat the current root relay, `main.billy_complete`'s `grok-research.md`
  (research97, accessed 2026-07-31), as the cited evidence authority. Its
  primary UI surface is `https://mit.billy.dk/`, while
  `https://www.billy.dk/api/` is the official API document and
  `https://api.billysbilling.com/v2` remains API-client-only.
- Reconcile that evidence with the approved design; the current `auth_status`,
  `auth_login_start`, and `auth_login_wait` implementations; and the existing
  UI/auth wiki pages.
- Select outcome 2: no `ui_*` read workflow is currently justified. A login
  page check would duplicate `auth_status`; organisation selection and session
  restoration need credentialed, non-production observation before their own
  shared `auth_*` contracts can be named.

## Deliverable contents

1. State the bounded decision and why neither a generic browser wrapper nor a
   duplicate `ui_*` probe is valid.
2. Specify the existing stable shared-auth interface: empty strict input,
   `AuthStatusSuccess(status=AUTH_REQUIRED)` or typed `ToolError`, its exact
   unauthenticated signature checks, egress scope, and fail-closed outcomes.
3. Preserve only observed selectors: email, password, remember-me, and the
   data-cy login button; allow exact labels `Log in` or `Log ind`; explicitly
   reject form or `button[type=submit]` assumptions. Include the DA locale plus
   Accept-Language requirement.
4. Define bounded offline fake-page/resolver test cases and explain that no
   authenticated DOM assertion, independent business read-back, live result,
   or vision result may be fabricated.
5. List exact credentialed non-production blockers for post-login selectors,
   organisation choice, and session restoration; identify the applicable UI
   inventory families as red until DOM, independent API read-back, and vision
   evidence exist.
