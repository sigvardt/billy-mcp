# 84.1 Wave-5i sales-tax account and meta-field product

## Scope and decision

Implement the accepted offline-only Wave-5i slice without fresh research. This
is a leaf node (`max depth`, `max children`, and `max descendants` are all
zero), so all work remains local. Preserve the shared write protocol,
Wave-5g sales-tax module, and attachment module unchanged.

## Implementation

1. Add `src/billy_mcp/api/sales_tax_account_meta_writes.py`, following the
   accepted typed ticketed-write pattern. Define strict, alias-aware outer
   Pydantic preview inputs for opaque `salesTaxAccount` and `salesTaxMetaField`
   maps, route-id checks for updates, and id-only deletes. Register exactly the
   twelve named preview/execute tools with one server-owned execute name per
   `WriteOperationSpec`.
2. Bind both families to the shared `WriteProtocolService` with client-relative
   `/salesTaxAccounts` and `/salesTaxMetaFields` paths, matching singular and
   primary plural roots, `additional_plural_roots=()`, canonical effects, and
   no retry path.
3. Register the new module once from `create_server`, retaining its existing
   shared `ConfirmationStore` and `WriteProtocolService`.

## Evidence and coverage

4. Add locked-transport contract tests for flat schemas, opaque payloads,
   non-mutating previews, exact request shapes and escaped paths, bodyless
   deletes, root/deleted-metadata mapping, absent-root handling, typed client
   errors, one-request failure behavior, and ticket integrity boundaries.
5. Add root-server cross-executor tests proving same- and cross-resource
   executor mismatches neither consume a ticket nor issue HTTP, after which the
   correct executor can use the ticket.
6. Update only the six documented manifest rows through
   `OFFLINE_API_IMPLEMENTATION_EVIDENCE`, the server registry expectations, and
   generated coverage artifacts. The intended result is 220 `api_*` tools and
   157 implemented/contract-tested API rows, with all live/UI/vision/bulk
   state still fail-closed.

## Verification and handoff

7. Run focused suites, formatting, Ruff, Pyright, coverage generation and
   policy checks, then the repository non-live suite. Inspect diffs to ensure
   only owned product and six-row coverage files changed.
8. Commit through Fractal, record the tested commit and remaining fail-closed
   boundary to the parent, fold concise terminal state into private memory, and
   finish without claiming the parent-owned Grok product review.

## Post-Mortem

- Delivered the isolated account/meta-field ticketed-write module and a single
  root registration using the existing shared confirmation service.
- Added locked-transport contract coverage for all six CUD shapes plus root
  same- and cross-resource executor protection.
- Generated evidence advances exactly the six frozen rows to 157 offline
