# 4.1 Phase 0 shared foundation

## Scope and constraints

Implement this leaf's concrete Phase 0 foundation under `src/billy_mcp/` and
`tests/unit/`; leave root-owned `models.py`, package metadata, coverage
manifests, scripts, CI, README, and wiki unchanged. The cited research freezes
the API host, token header, paging shape, two known 401 error codes, and the
headless-only browser rule. No `api_*` or `ui_*` domain tool may be registered.

This is solo work because all three child limits are zero. The coverage
inventory is intentionally an integration boundary: load its four committed
files when present, and return a typed unavailable error while they are absent.

## Implementation

1. Add typed configuration and secret resolution.
   - Keep `https://api.billysbilling.com/v2` immutable.
   - Resolve `BILLY_API_TOKEN` before an organisation-aware keyring lookup.
   - Model selected organisation, external persistent browser profile, and
     canonical allowed upload roots without retaining serialisable secrets.

2. Add shared safety primitives.
   - Implement recursive structured redaction for sensitive keys and
     authorization header forms.
   - Translate sanitised Billy error envelopes to root-owned `ToolError`, with
     both researched 401 codes mapped to `AUTH_REQUIRED`.
   - Build a locked, injectable HTTP client that accepts relative API paths
     only, constructs list paging from `page` and `pageSize`, strips the
     documented logger prefix before JSON parsing, and never retries writes.

3. Add confirmation and browser runtimes.
   - Implement a lock-protected, in-memory, opaque ticket store using at least
     256-bit randomness, five-minute-or-shorter TTLs, canonical JSON bindings,
     and one-use consumption checks.
   - Bind and compare tool, organisation, target, request, expected state,
     file digest/path, and normalized destination. Reject malformed tickets,
     expiry, replay, and every binding mismatch with stable errors.
   - Implement a bounded Playwright persistent-context wrapper with injected
     launch support for tests, forced `headless=True`, a trusted exact-host
     egress policy, and no trace/frame/HAR or desktop-window operations.

4. Add coverage loading and the FastMCP stdio shell.
   - Define typed coverage report/status models and a loader requiring the
     inventory manifests plus generated status; never infer a green result.
   - Register only typed `coverage_status` and `coverage_report` tools. Return
     the loader's stable typed error when the sibling manifests are not yet
     merged.

5. Add focused unit tests alongside each module.
   - Configuration precedence and secret-free serialisation.
   - Recursive redaction and both documented authentication envelope mappings.
   - Ticket entropy, expiry, replay, tampering, and every canonical binding.
   - API host/path lock, header policy, page/pageSize bounds, no `offset`,
     logger-prefix JSON parsing, and read-only retry behaviour.
   - Headless persistent context arguments and denied browser destinations with
     fake Playwright objects; do not open a browser.
   - Missing-manifest coverage errors and FastMCP registration containing only
     the two real coverage tools.

## Verification and handoff

Run formatting, lint, strict Pyright, the focused unit suite, repository policy
check, and the node test script. Commit only owned files. Report the module and
test results to the parent, explicitly noting the coverage-manifest merge
boundary; then complete the node once all checks pass.

## Post-Mortem

- Accomplished: implemented the configuration, redaction/error, confirmation,
  locked-client, headless-browser, coverage, and FastMCP modules with focused
  security tests.
- Deviation: the coverage loader initially assumed generic list keys; review
