## Design

### Tools (owned file only)

Implement in `src/billy_mcp/ui_writes/files.py`:

- `UiFilesCreatePreviewInput`: `path`, `filename` (unique tagged display
  name), optional `organization_id`. Extra fields forbidden. Path must
  resolve to a regular file. If `BILLY_UPLOAD_ROOTS` is set, the resolved
  path must stay under a configured root (same containment idea as API
  upload; do not copy the API HTTP client).
- `UiFilesCreateExecuteInput`: `confirmation_ticket` only.
- Preview success: reuse `UiWritePreviewResult` (or a files-shaped twin with
  the same fields). `canonical_request` includes resolved path, `sha256`,
  size, and filename. Never include file bytes.
- Execute success: non-sensitive result (`filename`, optional UI row id,
  `deleted` after cleanup). No download URLs.

`register_ui_file_write_tools(server, protocol, submitter=None)` keeps the
two-arg root call. Optional `submitter` is for tests.

### Ticket bind

Preview calls `protocol.preview(execute_tool_name="ui_files_create_execute",
file_path=<resolved>, file_digest=<sha256>, ...)`.

Execute:

1. `protocol.consume(..., execute_tool_name="ui_files_create_execute")`
2. Re-resolve the bound path and re-hash. If path or digest (or size)
   differs, return `FILE_CHANGED` and do not submit.
3. Call `submitter` only after a successful consume + identity match.

Preview never calls `submitter`. Execute never talks to
`BillyHttpClient`.

### Submitter (UI lane, not HTTP)

Default submitter uses `BrowserRuntime` as a helper to open a logged-in
page, then drives Bilag itself. Do not add methods to `browser.py`. Do not
treat `BrowserRuntime` as the qualification proof.

Offline tests inject a recording submitter that never opens a browser.

Live submit (only after radio go-ahead):

- Disposable fixture file outside git, under a configured upload root
  (node `tmp/` or `~/.local/share/billy-mcp/`).
- Unique tagged filename, e.g. `MCP-TEST-ui-files-<hex>.txt`.
- `set_input_files` on Bilag `input[type=file]`; wait for the tagged name.
- Independent second ephemeral UI session read-back of that name.
- Four-state frames: list before, after preview (unchanged), after execute,
  after delete. Purge frames. Store only a `VisionEvidenceRecord`.
- Delete the uploaded row through the UI. If delete chrome is still absent
  after a dry look (research185 found none on empty Bilag), **do not
  submit**. Record that as a concrete live blocker.

### Offline tests (`tests/unit/test_ui_files_writes.py`)

Qualify only through `FastMCP.call_tool`. Shared clock for expiry.

Must cover:

1. Register exactly `ui_files_create_preview` and
   `ui_files_create_execute` (flat schemas; execute has only
   `confirmation_ticket`).
2. Preview binds resolved path + sha256; submitter call count is 0.
3. Execute once: submitter called once with the bound identity.
4. Replay: `CONFIRMATION_CONSUMED`; submitter still 1.
5. Expiry: advance clock past TTL; `CONFIRMATION_EXPIRED`; no submit.
6. Wrong tool: issue a ticket for another execute name on the same
   protocol, then call `ui_files_create_execute`; `CONFIRMATION_MISMATCH`;
   no submit.
7. After preview, change bytes or replace/move the path; execute returns
   `FILE_CHANGED`; no submit.

Extend node `scripts/test.sh` to run
`uv run pytest tests/unit/test_ui_files_writes.py -q`.
