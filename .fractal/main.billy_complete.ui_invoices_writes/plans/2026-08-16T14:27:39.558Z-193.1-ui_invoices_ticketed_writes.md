## Design

Preview writes nothing. It validates a draft-only request, then
`protocol.preview(...)`.

Execute accepts only `confirmation_ticket` (`UiWriteExecuteInput`). It
`protocol.consume`s for the exact execute tool name, then calls an injected
submitter. Tests inject a recorder that never talks to Billy. Default submitter
must still refuse send/email/Godkend even if a later live slot opens.

Fail closed on preview and execute if the bound request asks for send, email,
Godkend, Godkend og send, or any non-draft save.

CTA for create is `Gem som kladde` only. Update is draft save on the edit
surface. Delete is Mere then Slet, drafts only.

Tools (flat Pydantic, no nested `input`):

| Tool | Preview fields | Execute fields |
| --- | --- | --- |
| `ui_invoices_create_preview` | contact/name tag, line description, draft-only action | — |
| `ui_invoices_create_execute` | — | `confirmation_ticket` |
| `ui_invoices_update_preview` | invoice id, draft field patch, draft-only action | — |
| `ui_invoices_update_execute` | — | `confirmation_ticket` |
| `ui_invoices_delete_preview` | invoice id, draft-only action | — |
| `ui_invoices_delete_execute` | — | `confirmation_ticket` |

Unique tagged names in canonical_request (prefix such as `MCP-UI-INV-`).
Organization id binds when the caller supplies it.

Execute after consume does not call the Billy HTTP API. Offline submitter
records the prepared request only.

## Offline tests (must pass)

Build a local FastMCP, register the family, inject a recording submitter and a
clocked `ConfirmationStore`. Zero HTTP to `api.billysbilling.com`.

- Six tools registered; execute schemas are `{confirmation_ticket}` only
- Preview issues a ticket and the recorder stays empty
- Create execute once: recorder sees one draft create
- Replay: `CONFIRMATION_CONSUMED`
- Expiry past `MAX_TICKET_TTL`: `CONFIRMATION_EXPIRED`
- Create ticket on delete execute: `CONFIRMATION_MISMATCH`
- Send/email/Godkend preview rejected; recorder empty
- Extra fields forbidden on preview and execute inputs

Qualify only through `server.call_tool`. Do not instantiate `BrowserRuntime` in
the unit file.
