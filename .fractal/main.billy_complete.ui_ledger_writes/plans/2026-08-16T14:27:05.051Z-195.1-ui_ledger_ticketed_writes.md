## Design

### Tools

| Preview | Execute | Preview inputs (flat, extra=forbid) |
| --- | --- | --- |
| `ui_daybooks_create_preview` | `ui_daybooks_create_execute` | `name` (min 1). Tag names `MCP-LEDGER-` plus a unique suffix. |
| `ui_daybooks_delete_preview` | `ui_daybooks_delete_execute` | `id` (min 1) |
| `ui_daybook_transactions_create_preview` | `ui_daybook_transactions_create_execute` | `daybook_id` (min 1), `text` (min 1) |
| `ui_transactions_create_preview` | `ui_transactions_create_execute` | `text` (min 1) |

Execute tools take only `confirmation_ticket` via `UiWriteExecuteInput`.

`execute_tool_name` on each preview must be the matching execute name.

### Preview

Call `protocol.preview(...)`. Return `UiWritePreviewResult`. Do not open a
browser. Do not construct `BillyHttpClient`. Bind
`expected_effect_state` with `action` + `resource` (`daybook` /
`daybookTransaction` / `transaction`).

### Execute

Call `protocol.consume(input, execute_tool_name=...)`. On `ToolError`, return
it. On success, return a family result with `submitted=false` and a
non-secret `blocker` string. Do not click Billy. Do not call the HTTP API.

Why fail-closed instead of submitting:

1. Register is `(server, protocol)` only. No submitter can be injected without
   editing `server.py`.
2. `browser.py` has open-only methods. Adding clicks here would duplicate
   browser code we are forbidden to edit.
3. Parent hold: no live submit until root radios a slot.
4. Daybook transaction and Posteringer create stay unsubmitted until a delete
   path is proven. Daybook create is only live-eligible after a matching
   delete is proven on the same tagged record.

This is a recorded live blocker, not an unsafe skip: execute is defined as
ticket consume plus refuse mutation. A later root wiring can add a submitter.

### Offline tests (`tests/unit/test_ui_ledger_writes.py`)

`asyncio.run(server.call_tool(...))` and read `structured_content`.

1. Register exactly the eight names. Execute schemas are only
   `confirmation_ticket`. No nested `input`. `additionalProperties` false.
2. Preview each family. Assert ticket + `expires_at`. Assert no
   `BillyHttpClient` / no request to `api.billysbilling.com`.
3. Execute once: consume succeeds, `submitted` is false.
4. Replay: `CONFIRMATION_CONSUMED`.
5. Expiry: clock past `MAX_TICKET_TTL` → `CONFIRMATION_EXPIRED`.
6. Wrong tool: create ticket into delete execute → `CONFIRMATION_MISMATCH`.
7. Extra preview fields rejected (pydantic extra=forbid).

Build the server with `FastMCP(...)` + `UiWriteProtocol(ConfirmationStore(clock=...))`.
Do not use `create_server` or `BrowserRuntime`.
