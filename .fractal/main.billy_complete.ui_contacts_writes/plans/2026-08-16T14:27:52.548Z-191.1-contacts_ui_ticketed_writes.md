## Design

Reuse `UiWriteProtocol` and `ConfirmationStore`. Preview calls
`protocol.preview` only. Execute accepts only `confirmation_ticket` via
`UiWriteExecuteInput`, then `protocol.consume`.

Root already calls `register_ui_contact_write_tools(server, ui_write_protocol)`.
Keep that two-arg call valid. Optional third argument `actor` is for tests.

### Tools (flat, extra forbid, no nested `input`)

| Tool | Inputs | Effect |
| --- | --- | --- |
| `ui_clients_create_preview` | `name` (min 1) | Ticket. No UI submit |
| `ui_clients_create_execute` | `confirmation_ticket` | Consume, then actor create |
| `ui_clients_update_preview` | `name`, `new_name` (min 1) | Ticket. No UI submit |
| `ui_clients_update_execute` | `confirmation_ticket` | Consume, then actor update |
| `ui_clients_delete_preview` | `name` (min 1) | Ticket. No UI submit |
| `ui_clients_delete_execute` | `confirmation_ticket` | Consume, then actor delete |

Locate contacts by unique tagged name, not API id.

Canonical requests:

- create: `{"action":"create","name":"..."}`
- update: `{"action":"update","name":"...","new_name":"..."}`
- delete: `{"action":"delete","name":"..."}`

### Actor seam (do not edit `browser.py`)

`ContactUiActor` protocol with `submit_create` / `submit_update` /
`submit_delete`. Offline tests pass a recording fake. Live test injects a
Playwright actor on a logged-in `BrowserRuntime`. Production `actor=None`
builds that runtime from `AppConfig` only at execute time.

Preview must not call the actor. Execute calls it once with the bound request.

UI steps (live actor only):

1. Create: open `/:org_slug/clients`, click **Opret kontakt**, fill `name`,
   click **Gem**. Never API.
2. Update: open the tagged row, **Ret**, change `name`, **Gem**.
3. Delete: open the tagged row, **Mere**, confirm **Slet kontakt**.

### Qualification

Every pass proof is `FastMCP.call_tool`. Unit tests build a tiny server and
register only this family. Live tests do the same, then a second independent
UI session lists customers and matches the tag.

### Offline cases (all via `call_tool`)

- Registers exactly the six tools; execute schemas are `{confirmation_ticket}`
- Preview returns ticket; actor call count stays 0
- Execute once: actor called once with the bound request
- Replay: `CONFIRMATION_CONSUMED`
- Expiry: clock past `MAX_TICKET_TTL` → `CONFIRMATION_EXPIRED`
- Wrong tool: create ticket into update/delete execute →
  `CONFIRMATION_MISMATCH`

Use an injectable `ConfirmationStore(clock=...)`.

### Live cases

- Unique tag `MCP-UI-C-<8hex>` (and `-U` after update)

  update, and after delete
- Four-state capture (before, after create, after update, after delete)

  if delete can still run
